# 알약 식별 후보 검토와 추가 확인

다중 알약 식별은 약품을 자동 확정하는 기능이 아니라 사용자가 비교할 후보를 제시한다.
사진에 없는 각인이나 서로 같은 외형은 추가 정보 없이 확정할 수 없다.

## 기본 기능 제공

v0.2.0에서는 단일·다중 알약 식별을 별도 설정 없이 함께 제공한다. 한 장에서 여러
알약을 찾거나 알약별 앞뒷면 사진을 추가할 수 있으며, 최대 10개 제한과 후보별 사용자
확인 절차는 유지한다. 실험실 메뉴와 전용 설정을 제거하고 구형 실험실 저장값은
무시한다. 기존 글씨 크기·언어·알림 설정과 복약정보는 변경하지 않는다.

## 주요 동작

- 기본 5개 후보의 경계와 동점인 제품도 반환한다. 화면에서는 5개씩 더 펼쳐 본다.
- 응답은 알약당 최대 100개로 제한한다. 그 밖에도 동점 후보가 있으면 목록이
  완전하지 않음을 표시하고 같은 알약의 뒷면 추가를 안내한다.
- 번호별 원본 영역만 잘라 다시 분석하거나, 사용자가 동일 알약임을 확인한
  뒷면 사진과 함께 기존 단일 알약 분석 API로 비교한다. 앞뒷면을 자동 대응하지 않는다.
- 퍼센트를 정답 확률처럼 표시하지 않고 '추가 확인 필요' 또는 '비교 후보'를 표시한다.
- 성공한 재분석은 해당 알약의 후보 선택만 초기화한다. 취소나 실패는 기존 결과와
  다른 알약의 선택을 유지한다. 저장 전 후보와 복약 일정 확인은 항상 필요하다.

## 구조

`PillIdentificationUI → IdentifyPill → PillImageCropService → 기존 후보 분석 API`

UI는 번호·사진 출처·사용자 확인을 담당하고, Control은 자르기 서비스와 기존
분석 API를 연결한다. 새 crop 서비스는 별도 isolate에서 EXIF 방향을 보정한 후
원본 영역을 먼저 자른다. 10MB/24MP 입력 상한을 적용하며 디스크에 결과를 저장하지
않는다. 작은 영역은 흰 여백만 추가하고 각인 생성이나 인위적인 픽셀 확대는 하지 않는다.
서버의 기존 사진 검증, 요청 제한, 일치도 계산과 필수 확인 정책은 유지한다.

## 검증 범위

자동 테스트는 동점 후보 보존·응답 상한·뒷면 비교·번호별 재분석·선택 취소와 실패 복구,
작은 화면/큰 글씨, EXIF 회전·영역 자르기를 다룬다. 실제 사진에 대한 식별 성능은
별도의 다양한 촬영 사진으로 평가해야 하며 이 구현만으로 정확도를 보장하지 않는다.
