# 병원·약국 및 채팅 변경 검증

## 범위

`beta/v0.2.0`의 병원 조회, 공통 지도·필터, 장소 공유, 채팅 미확인 표시,
알림 진입과 보호자 홈 상태 표시를 검증했다. 로컬 실제 API 키와 기기 설정은
검증 기록 및 저장소에 포함하지 않는다.

## 자동 검증

- Backend 전체: 788 passed, 2 skipped, 21 subtests passed.
- Flutter 전체: 1,164 passed.
- Flutter analyze: No issues found.
- 변경 UML 원본 8개와 PNG를 함께 갱신하고 PlantUML 렌더링 성공을 확인했다.
- 전체 테스트에서 이전 `읽음` 문구와 정방향 목록 위치, 필터 즉시 적용을
  기대하던 회귀 테스트를 새 UX에 맞췄다. 읽음 이벤트 후 `1`이 다시 나타나지
  않는지, 이전 대화를 볼 때 스크롤과 미확인 상태가 유지되는지도 검사한다.

주요 회귀 사례는 다음과 같다.

| 영역 | 확인 내용 |
| --- | --- |
| 병원 API | 좌표·필터 검증, 인증, 응답 계약, 제공기관 오류, 호출량·페이지·시간 제한 |
| 공휴일 | XML 결과 검증, 월별 캐시, 실패 재호출 억제, 모르는 날짜를 평일로 단정하지 않음 |

| 보호자 홈 | 로딩·실패 중 기존 카드 구조 유지, 성공 이후 환자 일정 표시 |

## 에뮬레이터 확인과 제한

로컬 데모 실행기를 통해 환자와 보호자 에뮬레이터에 새 APK를 설치하고
두 홈 화면이 정상적으로 열리는 것을 확인했다. 앱 데이터와 위젯을 지우지
않는 기존 갱신 방식을 유지했으며, 해당 실행의 앱 오류 로그도 확인했다.

이 데모는 로컬 인증 비활성 환경이다. 실제 운영 Firebase 계정의 FCM 전달,
제조사별 배터리 제한, 실제 기기의 외부 전화·길찾기 앱, 모든 지역의 제공기관
데이터 정확성까지 검증했다는 의미는 아니다. Backend 테스트의 건너뛴 두 사례도
통과로 집계하지 않는다. 병원 운영 정보는 방문 전에 기관에 확인해야 한다.
