# 처방 약명 매칭과 후보 확인

## 목적과 판단 범위

OCR 오타를 찾는 유사 검색은 유지하되 이름이 비슷하다는 이유로 함량·제형이 다른
제품을 자동 연결하지 않는다. 예를 들어 `아스피린정 100mg`을
`바이엘아스피린정500밀리그람`으로 확정해서는 안 된다. 제품명 식별 규칙이며,
치료상 대체 가능성이나 적절한 복용량을 판단하는 기능은 아니다.

## 서버 흐름

1. 함량·괄호를 포함한 원문부터 검색한다. 검색 방식에 따라 최대 2·4·8개 검색어를
   순차 조회하며, 원문·괄호 바깥 제품명·괄호 안 이름과 구조적 변형을 OCR 오타
   변형보다 우선한다. 잘린 괄호 뒤 설명은 보조 검색어에서만 제외한다.
2. `original_text`가 있으면 이를 자동 보정 이전의 근거로 사용한다. 넓힌 검색어가
   원문의 함량을 지우더라도 후보 검증 기준은 바뀌지 않는다.
3. `medication_match_safety`의 공통 규칙으로 OCR 로컬 교정, AI 교정과
   상세조회 로컬 목록·Redis·공공 API 응답을 검사한다. 명시된 함량이 다르면
   제외한다. 후보에 함량이 없으면 수동 확인 후보로는 남길 수 있지만 자동
   연결하거나 OCR 이름 보정에 사용하지 않는다. 확인 가능한 정제·캡슐 등 제형과
   서방·장용 표기도 비교하며, 밑줄 때문에 제형을 놓치지 않도록 정규화한다.
4. mg·g·mcg의 동등 단위, 한국어 단위, 농도 분모, 숫자 표기를 정규화한다.
   복합제의 함량은 개수까지 비교한다. 모든 성분·제형의 임상적 동등성을 판단하는
   규칙은 아니며, 정규화한 전체 이름이 다르면 유사도만으로 자동 확인하지 않는다.
5. 품목 코드 또는 이름·제조사로 중복을 제거한다. 정규화한 이름이 정확히 일치하는
   제품이 하나이고 후보 요약 누락이 없을 때만 `data`에 반환한다. 그 외 유효
   후보는 최대 다섯 개를 확인 전용 응답으로 반환한다. 표시 개수 제한 전에
   누적 후보 전체에서 동일명 복수 제품 여부를 판단한다.

## 검색 방식과 시간 제한

| 요청값 | 최대 검색어 | 조회 종료 기준 |
| --- | --- | --- |
| `fast` | 2개 | 원문과 괄호 바깥 이름을 우선하고 유효 후보가 생기면 종료 |
| `balanced` | 4개 | 기본값. 직접 이름과 구조적 변형을 우선하고 유효 후보가 생기면 종료 |
| `thorough` | 8개 | 후보를 누적하며 추가 검색. 요약 누락 없는 단일 정확 일치가 확인되면 조기 종료 |

방식은 검색 범위만 바꾸며 더 넓은 검색을 정확도 보장이나 안전 기준 완화로
설명하지 않는다. 모든 방식에 같은 서버 50초 제한을 적용하고, 시간 초과는
`504` 조회 실패로 전달한다. 제공자 오류와 시간 초과를 검색 결과 없음으로 바꾸지 않는다.
앱의 요청 제한은 기존 60초이며 계정 사용 중 응답의 제한적 재시도는 별도다.

앱은 검색 방식을 계정별 기기 설정으로 저장하고 일반 설정 서버 동기화에서 제외한다.
약품 조회 때 현재 선택값을 읽어 보내며, 없거나 지원하지 않는 기기 저장값은
`balanced`로 정규화한다. API는 지원하지 않는 요청값을 거부한다.

## AI 요약 부분 실패와 캐시

로컬 허가 카탈로그와 공공 허가 API는 후보별 요약을 함께 요청하되, 일부만 실패하면
성공한 요약은 원래 순서대로 유지한다. 내부 `MedicationLookupResult`는 상세 목록
`details`와 후보 요약의 완결 여부 `is_complete`를 함께 전달한다. 이 값은 조회한
후보에서 요약 실패로 누락된 제품이 있는지를 뜻하며, 전체 카탈로그를 빠짐없이
검색했다는 보장은 아니다. 한 제품의 요약에서 일부 안내 항목만 `정보 없음`인 경우와도
구분한다.

예를 들어 이름이 같은 품목 코드 A·B 중 B의 요약만 실패해 A만 남더라도 A를 자동
확정하지 않는다. `data=[]`, `candidates=[A]`, `requires_confirmation=true`,
`review_reason=ambiguous_product`로 보내 기존 후보 확인 화면을 사용한다.
이전 검색 변형이나 로컬 조회에서 확인된 요약 누락은 재정렬·이미지 보완·공공 조회로
넘어가더라도 지우지 않는다. 모든 후보의 요약이 실패하면 빈 성공 결과가 아니라
조회 오류로 처리한다.

Redis의 검색 결과 캐시는 후보 요약이 모두 성공한 비어 있지 않은 목록만 7일간
보관한다. 부분 목록은 저장하지 않으므로 다음 조회에서 실패했던 후보도 다시
요청한다. 로컬 카탈로그에 개별 저장된 성공 요약은 계속 재사용할 수 있다.
구버전의 목록에는 누락 여부가 없으므로 기존 `drug_info:` 키를 읽거나 옮겨 쓰지 않고
`drug_info:v2:`를 사용한다. 기존 키는 원래 만료 시간에 따라 정리되며, 첫 조회는
로컬 카탈로그 또는 공공 API에서 결과를 다시 확보한다. 원문과 검색어가 다르면
캐시 키에도 두 값을 함께 사용한다. 캐시 목록에 해석할 수 없는 후보가 섞여 있으면
그 후보만 버리는 대신 전체 캐시를 미스로 처리한다.

## API 계약

기존 `POST /api/v1/medication/identify`에 선택 필드를 추가한다.

| 필드 | 의미 |
| --- | --- |
| 요청 `extracted_text` | 현재 조회할 약명 |
| 요청 `original_text` | 자동 보정 전 OCR 근거. 사용자가 직접 이름을 수정·추가·선택한 경우 앱은 생략한다. |
| 요청 `search_mode` | `fast`, `balanced`, `thorough` 중 하나. 생략하면 `balanced`다. |
| 응답 `data` | 자동 확인 가능한 상세 정보. 확인 전용 응답에서는 빈 배열이다. |
| 응답 `candidates` | 직접 확인할 후보 상세 정보. 전체 제품명과 `manufacturer`를 포함한다. |
| 응답 `requires_confirmation` | 후보를 선택·확인해야 하는지 여부 |
| 응답 `review_reason` | `ambiguous_product`, `not_found`, `strength_or_form` 등 조회 결과 구분 |

조회 위치에 따라 위험 후보가 이미 제외되면 빈 결과가 `not_found`로 반환될 수
있다. 사유만으로 원문 약의 실제 존재 여부를 단정하지 않는다. 후보 없음과
네트워크·인증·서버 실패는 별도 상태로 유지한다.

확인 전용 응답은 `success=true`여도 `data=[]`로 보낸다. 구형 앱이 첫 후보를
자동 채택하는 일을 막기 위한 계약이다. 새 앱도 복수 `data`를 반환하는 구형
응답에서는 첫 항목을 자동 채택하지 않는다. 다만 구형 서버의 단일 오매칭까지
새 앱만으로 방지하지는 못하므로 서버와 앱을 함께 갱신하고 서버를 먼저 배포한다.
이 약명 조회 보완에는 새 API 키나 데이터베이스 스키마 변경이 없다.
`MedicationLookupResult`는 서버 내부 전달 형식이며 API 응답에 새 필드를 추가하지 않는다.

## 화면과 상태

- OCR 인식 직후 약품 1차 조회를 자동 시작한다. 중간 분석 시작 확인은 없지만
  후보 선택과 약 저장은 별도 사용자 동작으로 유지한다.
- 인식 중에는 문자 인식·정보 정리 단계를, 조회 중에는 실제 완료 건수를 표시한다.
  후보 없음·조회 실패도 완료 건수에 포함하되 사용 중 재시도는 중복 집계하지 않는다.
- 검토 화면은 약별 세로 카드와 조회 상태별 개수를 제공한다. 확인 완료·후보 있음·
  검색 결과 없음·조회 실패·조회 전을 구분하고 전체 실패도 같은 화면에서 재시도한다.
  원문은 검증·복구를 위해 보존하되 카드 목록에 반복 표시하지 않는다.
- 검토 요약과 결과의 분석 약 개수는 진입 즉시 상단에 고정한다. 중앙 2초 대기나
  슬라이딩을 사용하지 않으며 아래 본문을 바로 탐색할 수 있다.
- 확인이 필요한 각 카드에 후보 확인 동작을 제공한다. 확인된 카드는 편집 잠금을
  유지하며 취소선 대신 확인 상태로 표시한다.
- 선택창에는 OCR 원문 또는 사용자가 수정한 이름, 후보 제품명·제조사를 표시한다.
  초기 선택은 없고 제품을 고르기 전에는 확인 버튼을 사용할 수 없다.
- 확인하면 그 행만 검증된 결과로 이동한다. 복용량·기간·시간대·원문은 유지하고
  `nameCorrectionSource=user_selection`을 남긴다. 확인 자체는 약 저장이 아니다.
- 다른 미확인 행은 그대로 남기며, 전체 확인 뒤 결과 보기 또는 별도 확인을 거친
  '확인된 약만으로 계속' 흐름으로 이동한다. 후보 확정 뒤 이미 확인된 약을
  불필요하게 다시 조회하지 않고, 찾지 못한 약을 임의의 제품으로 채우지 않는다.
- 선택 취소는 확정하지 않는다. 이름 수정·새 분석·흐름 초기화로 무효가 된 후보나
  늦은 응답은 적용하지 않는다. 용량만 수정하면 기존의 명시적 이름 선택 근거를 유지한다.

## 조회 충돌 복구

계정 보호용 잠금은 유지한다. 앱은 기존 여섯 건 단위 동시조회가 끝난 후,
정확히 `503`과 `This account is busy. Retry the request shortly.`가 반환된
요청만 `Retry-After`에 따라 순서대로 한 번 재시도한다. 재시도도 실패하면
미일치가 아니라 조회 오류로 안내한다. 다른 503과 인증 오류를 무한 재시도하지 않는다.
대기·재시도 전후에 현재 분석인지 확인하므로 취소된 처방을 다시 채우지 않는다.
