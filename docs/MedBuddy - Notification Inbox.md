# 홈 메뉴와 알림함

## 화면 구성

- 홈 2×2: 약 등록·식별, 건강 관리 추천 / 근처 운영 약국, 환경설정.
- 상단 종 버튼은 미확인 알림 개수를 표시하고 알림함을 연다.
- 복약 알림 설정은 환경설정의 복약 및 알림 분류와 일정 화면에서 계속 제공한다.
- 알림함은 종류별 탭 없이 모든 알림을 최신순으로 모아 보여주고, 읽음 처리와 개별·전체 삭제를 제공한다.
- 선택 버튼이나 알림 길게 누르기로 선택 모드에 들어가 개별·전체 선택 후 삭제한다. 선택 중 누르기는 이동 대신 선택을 바꾸며, 삭제 확인 중 새로 도착한 알림은 포함하지 않는다.
- 채팅 알림 제목은 현재 채팅 목록과 동일한 상대 이름을 사용한다. 등록된 환자 별칭을 우선하고, 기존 알림에도 이름 변경을 반영한다. 연동을 찾지 못했거나 내용 숨김 설정인 경우에는 일반 알림 제목을 유지한다.
- 알림 선택은 기존 채팅·환자 일정·본인 일정 이동 처리기를 사용한다. 기존 세션·연동 검증은 유지한다.

## 저장과 경계

`NotificationInboxUI → ManageNotificationInbox → NotificationInboxStore → NotificationInboxEntry`

상대 이름은 홈이 관리하는 같은 계정의 `ManageChatList`에서 조회하므로 알림마다 별도 서버 요청이나 이름 사본을 만들지 않는다. 이 제목 변환은 앱 알림함에 적용하며 시스템 푸시 제목 정책은 변경하지 않는다.

알림 표시는 기존 서비스가 담당한다. 로컬 알림과 수신 계정이 확인된 푸시는 계정별 기기 저장소에 내역을 남긴다. 서버 알림함이나 다른 기기와의 동기화는 이번 범위에 포함하지 않는다. 적용 전 알림은 복원하지 않는다.

알림마다 별도 키로 저장하여 서로 다른 이벤트의 동시 저장이 덮어쓰이지 않도록 한다. 같은 식별자의 알림을 다시 받아도 읽음·삭제 상태는 유지한다. 최근 90일을 보관하고 최대 500개를 최신순으로 표시한다. 채팅 알림은 수신 당시 표시가 허용된 메시지 내용을 최대 120자 미리보기로 보관한다. 종류만 표시하도록 설정했거나 본문이 없으면 기존 안내 문구를 사용한다. 푸시의 빈 미리보기는 서버의 내용 숨김 결정이므로 다른 본문으로 대체하지 않는다.

기존에 내용 없이 저장한 알림은 그대로 유지하고, 변경 이후 받은 알림부터 미리보기를 표시한다. 미리보기는 수신 당시 기록이므로 대화에서 메시지가 삭제되어도 별도로 남을 수 있다. 알림 삭제는 실제 메시지, 연동, 복용 기록을 삭제하지 않는다.

복약 예약은 성공적으로 등록한 시각부터 내부적으로 보관하되, 예정 시각이 지나야 목록에 표시한다. 예약 취소·변경 시 미래 기록은 제거하고 지난 기록은 유지한다. 따라서 복약 내역은 **예약 시각 기준의 알림 이벤트이며, 운영체제에서 실제로 알림을 전달했다는 증명이나 복용 완료 기록이 아니다.** 권한·절전 정책 등에 따라 실제 표시와 차이가 날 수 있다.

푸시는 전경 수신, 지원되는 백그라운드 콜백, 알림 열기에서 기록한다. 앱 강제 종료나 OS가 직접 처리하는 푸시는 열기 전까지 저장되지 않을 수 있으므로 모든 서버 발송 이력을 보장하지 않는다. 수신 계정 정보가 없는 오래된 푸시는 다른 계정에 섞이는 것을 막기 위해 알림함 저장에서 제외한다.

## 검증

계정 분리, 같은 식별자의 중복 수신, 읽음·삭제 유지, 예정 시각·취소, 보관 기간, 손상 항목 격리, 저장 실패 복구, 푸시 수신 계정, 미리보기·내용 숨김, 최신순 통합 목록·삭제 확인, 작은 화면과 큰 글씨를 테스트한다. 홈 메뉴와 기존 알림·채팅·접근성 회귀 테스트도 유지한다.

로컬 환자·보호자 에뮬레이터에서 새 채팅 미리보기와 복약 예약 알림이 같은 목록에 표시되는 것을 확인했다. 이는 로컬 데모 검증이며 실제 FCM 전송, 강제 종료·재부팅·절전 상태의 전달 보장은 별도 실기기 검증 대상이다.
