# MedBuddy 1.1.0

## Status

- Version: `1.1.0+30` (server `1.1.0`); the first 1.1.0 build was `1.1.0+29`
- Baseline: `v1.0.1`
- Release branch: `v1.1.0`
- Target tag: `v1.1.0`
- Platform: Android
- Publication status: released on 2026-11-28

This document records the 1.1.0 boundary. The GitHub release notes carry the final
commit identifiers and signed artifact checksums.

## Changes

- **Release line:** the branches merged before the graduation exhibition were deleted,
  and signed off-Play builds come only from `v1.1.0`.
- **Photo dose recording:** 약 등록 > 사진으로 복용 기록. A photo of the pills in hand is
  matched with the user's own medicines on the server (imprint, or a balanced group of
  look-alike plain tablets; anything weaker is asked), each medicine goes to its own slot
  (late doses flow back to an unhandled slot until the next reminder; a medicine taken in
  the recent-dose spacing (two hours, or half the gap to its previous slot when slots are
  close; four hours for as-needed), or not due yet, is shown and not recorded), and one large
  confirmation records everything in one transaction at the photo time. As-needed
  medicines are recorded once. Design and rules: `docs/Photo Dose Recording.md`.
- **Home:** 약 등록, 약 관리 and 약 검색 are separate green buttons; buttons show only a
  large icon and a name; the four rows share the remaining height (60-112 dp) without
  scrolling, also on a Galaxy Note10 with a schedule card shown. The home keeps the same
  layout at every font-size setting (other screens follow the setting); icons and long
  titles shrink slightly to fit.
- **Registration:** 낱알약 식별 opens the one-photo screen directly (one or several
  pills); camera/gallery and other choices are large tiles. The per-pill photo mode
  and the screens' unused direct-save paths were removed.
- **Pill identification:** the MFDS words for a logo or score line ("마크", "분할선") are
  no longer compared as imprint text, oval and oblong count as adjacent shapes, an empty
  photo is a photo problem (422) instead of an invalid response, and during a Gemini
  outage the Claude copy's photo verdict is passed on. Found in the 2026-11-28 phone test.
- **AI models:** every Gemini path uses `gemini-3.5-flash-lite` (was 3.1 Flash-Lite; same
  accuracy and lower latency in a same-input comparison). A fast Gemini failure is retried once
  on Gemini before Claude answers, and the Claude fallback default is `claude-haiku-5-5` with
  effort `high`. Set `PILL_IDENTIFICATION_MODEL_NAME=gemini-3.5-flash-lite` in
  `deploy/backend.env` (it overrides the default).
- **Matching safety:** "imprint" evidence now means the same text (not a one-letter neighbour
  such as "AN 400" for "AG 400") and ranks above look-only scores; an export-only product never
  competes with a domestic exact match; the prescription prompt keeps product names as printed
  instead of turning them into an ingredient or a similar product (the Claude copy had written
  "파모티정" for "파모터정").
- **Server:** three new endpoints, `POST /schedule/photo-intake/plan`,
  `/schedule/photo-intake/confirm` and `/ingredient-overlap`; version `1.1.0`. No
  migration or new configuration. Deploy the backend before distributing the app (older servers
  answer 404 and the app shows a connection problem).
- **Favorites (exhibition feedback):** the favorite star is larger (48 dp target, 32 px
  star) and drawn with a thick outline; a filled amber star marks a favorite. A star button
  above "현위치로" on the map shows favorites only: the list and markers keep only
  favorites, pharmacies switch to the all-pharmacies query while it is on (so closed
  favorites appear with their badge) and the previous filter returns when it is turned
  off. Favorites outside the current results are listed from a saved snapshot (name,
  address, telephone, location) with "운영 정보는 누르면 확인해요"; tapping one moves the
  map there and opens the live place. Back or the star button leaves the mode.
- **외출 전 약 챙기기 알림 (exhibition feedback):** on the schedule screen, a reminder at a
  chosen time (default 07:30) on chosen weekdays (월~일 in one row; 토 blue, 일 red) on days
  with a lunch or evening medicine. It names no medicine, has no actions and opens the
  schedule. Device-local per account; account deletion removes it.
- **Same-ingredient notice (exhibition feedback):** when the result screen opens after
  registration, the app sends the product numbers of the new medicines to
  `POST /api/v1/medication/ingredient-overlap`. The server compares their MFDS main
  ingredients with the account's active medicines and with each other. A shared ingredient
  shows an amber notice on the row ("…에도 같은 성분(…)이 들어 있어요. 함께 드셔도 되는지
  약사나 의사에게 물어보세요."). The numbers are used for this check only and are neither
  stored nor logged. For prescriptions, overlaps within the same prescription and refills of
  the same product are not shown. The change radar now splits combination products'
  ingredients as well. Dose adequacy is not judged.
- **Documentation:** UML (UC-39, `PhotoDoseRecording` sequence, class diagrams with the
  Claude outage fallback) updated; the user guide PDFs are not yet updated. The three
  exhibition-feedback features (build 30) are not yet in the UML or the user guide.


## Phone check of build 30 (2026-11-28)

The signed `1.1.0+30` arm64 APK was installed over 1.1.0+29 with `adb install -r` (data
kept) and checked against production after the server deploy:

- **Same-ingredient notice:** 낱알약 식별 with a photo of 타이레놀정500 and 게보린정 in a palm
  identified both; the result screen showed the amber notice on each row naming the other
  and 아세트아미노펜. Left without saving.
- **Favorites:** a starred pharmacy turned amber; the map star showed only that pharmacy and
  switched the query to all pharmacies; turning it off restored 현재 영업 중. The test
  favorite was removed again.
- **외출 전 약 챙기기 알림:** with a temporary lunch medicine on the phone's own schedule, the
  reminder set for 17:37 every day arrived at 17:37 ("약 챙기기" / "오늘 밖에서 드실 점심·저녁
  약을 챙겨 가세요."); tapping it opened today's schedule at 점심. The weekday row fits on
  the phone. The reminder, the temporary medicine and the home-schedule setting were put
  back afterwards.
- Not checked on the phone: the reminder on a locked screen, a favorite snapshot far from
  the current area (checked on the emulator), and the notice against an already saved
  medicine (covered by server tests).
