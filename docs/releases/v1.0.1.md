# MedBuddy 1.0.1

## Status

- Version: `1.0.1+28` (server `1.0.1`)
- Baseline: `v1.0.0`
- Release branch: `v1.0.1`
- Tag: `v1.0.1`
- Platform: Android
- Publication status: released on 2026-11-22 (signed build, server deploy and GitHub
  release)

This document records the 1.0.1 boundary. The GitHub release notes carry the final
commit identifiers and signed artifact checksums.

## Changes

- **Registration results:** prescription, pill-photo and manual entries end on one
  shared result screen with partial saves; selected pill candidates are reviewed with
  their source photos, and review galleries open centred with photo navigation.
- **Deferred details:** a saved medicine no longer waits for public-data lookups; the
  server fills blank details in the background after the save, only for the same
  unedited course.
- **Linked care:** a caregiver's chosen patient is shared by Home, Schedule and
  History; link codes confirm their use on both devices; a patient can complete a
  requested dose inside the chat.
- **Widgets:** linked-patient widgets refresh without opening the app, compact layouts
  navigate between slots and resize stably, and placement previews come in compact and
  expanded sizes.
- **Read-aloud position:** while a medication detail is read aloud on Android 8.0 or
  later, the sentence being spoken is highlighted in the name, usage or warning card
  and the screen scrolls to that card; the spoken text itself is unchanged.
- **Diagnostics and fixes:** pill analysis timeouts are classified and traced per
  stage, the dose store keeps transactions across Flutter engines, offline schedules
  are restored after cancelled saves, and incomplete catalogue markup is rejected.

## Review corrections (2026-11-16)

- **Caregiver alerts with an unreadable dose store:** the background caregiver task
  opened the dose store before anything else, so a store that could not be opened
  stopped the missed-dose check on every run. A store failure now skips only the
  caregiver widget refresh.
- **Chosen patient after a failed link read:** one failed link refresh reset the
  caregiver's chosen patient to the first link. The choice is now kept while links are
  unknown; access is still refused until they load.
- **Offline schedules after a refused save:** a save the app refused before sending it
  (a dose schedule that needs review) or a request validation reply counted as
  possibly saved, so today's cached schedule and the offline window were deleted.
  Both now restore the cache like the capacity refusal.
- **Save message language:** saving one row of a result showed the server's English
  text to Korean users; the message is now in the app language again.
- **Catalogue text with Korean labels:** a document containing "<주의>" or "<소아>" was
  rejected as markup, leaving the efficacy, usage or warning text empty. Tag names are
  ASCII, so such labels now stay as text.
- **Details after an early edit:** a course edited before its background lookup ended
  was replaced by a new row that never got the details; a regimen change now queues
  the lookup for the new course.
- **Multi-pill timeouts:** a provider transport timeout in multi-pill analysis was
  reported as an outage instead of a timeout, unlike the single-pill path.
- **Refactoring:** shared helpers for the enrichment identity filter, the manual entry
  route, the save guard, the chosen catalogue product, link dialogs and the chat dose
  key; the widget checks read their source without rewriting widget state, and push
  alerts are shown before the widget refresh hint.

## Review corrections (2026-11-20)

- **Read-aloud position:** the start-of-speech notice sent an empty range that the
  screen could never show; only engines that report ranges now send positions. The
  section check for the highlighted card is one shared helper.

## Security audit and review (2026-11-22)

A third audit with the security-audit skill covered the code changed since the second
audit (95 coverage units, 13 hunters, two coverage critics, independent verification of
every candidate). It confirmed four low-severity findings; all four are resolved.

- **Push tokens after a revocation:** the server reuses an account's revocation state
  for up to 30 seconds, so a session issued before the owner revoked all sessions could
  register its device again in that window and escape the later clean-up of old
  devices. A push registration made with a token issued before the account's current
  revocation time is now refused.
- **Address quota spent by refused requests:** for the AI, hospital and pharmacy
  routes the per-address daily allowance was charged before the account's own daily
  allowance, so one account that had used up its own allowance could keep spending the
  allowance shared by everyone on the same address. The account allowance is now
  checked first.
- **Repeated background detail lookups:** every duplicate save or replayed regimen
  change of a medicine with details the public data cannot fill started the public
  lookups and an AI summary again, outside the daily AI quota, and one account could
  fill the shared queue. A lookup that answered is not repeated for six hours, the AI
  summary runs only when it can fill a missing field, and one account holds at most
  four queued lookups.
- **Hospital search budget:** one account's daily searches could use up the shared
  hospital API budget for everyone (1,000 calls per operation a day on the development
  account). The hospital service moved to an operating account on 2026-11-22 (100,000
  calls per operation a day) and the server budget is now 80,000, far above what one
  account's daily search quota can spend. The pharmacy location service moved to an
  operating account the same day, and its budget is now 80,000 as well.
- **Forged slot-check action:** the caregiver request's "Taken" button runs only in the
  background handler, but the app also accepted the same action through the exported
  main activity, where another app could send it with a crafted payload (the
  patient's account hash was still needed). That path now ignores it.
- **Chat stream during an outage:** an open chat stream whose session check kept
  failing stayed open until its token expired. It now closes after three failed checks
  in a row and reconnects with a fresh token.
- **Save failure messages:** the shared result screen showed a generic message for a
  full pillbox or a lost connection, and a Korean user could see the raw validation
  reply of a refused request. Each failure kind has its own message again.

## Prescription envelope check (2026-11-23)

A real pharmacy bag with the name and date changed was registered on the phone after the
release; the assets were rebuilt from this fix.

- **Personal data in the sent text:** the bag's receipt printed "환 자 성 명" with a space
  between letters and "홍길동(060101-3)" beside it. The device filter did not read that
  label (the server's guard did) and treated neither the name nor the birth date with
  the sex digit as personal, so the row reached the server in the analysis text. The
  device labels now allow the same spacing as the server, and both sides treat a
  six-digit birth date followed by a single sex digit as an identifier.
- **Candidate review for every row:** all five products needed a manual pick although
  each search found exactly one, because catalogue names end in the ingredient. A
  trailing parenthesis alone no longer blocks auto-confirmation, and neither does a
  single commonly misread Hangul vowel when only one product fits (see the decision log).
  On the phone the same bag then showed all five rows as "약품 확인됨".
- **Not changed:** one dose printed as 0.5 tablets came back as 1 tablet and was
  corrected on the review screen; the recognised text is not kept, so it is not known
  whether the device OCR or the analysis misread it.

## Version label, Claude fallback and final assets (2026-11-24)

- **Settings version label:** the settings screen of the 1.0.1 build showed
  `MedBuddy v1.0.0`. No build passes `MEDBUDDY_APP_VERSION`, so the label used its
  default, which had not followed the pubspec. The default is `1.0.1`, and a test now
  fails whenever it differs from the pubspec version (PR #141).
- **Claude only on a Gemini outage:** with `ANTHROPIC_API_KEY` in `deploy/backend.env`,
  prescription text, pill photo, medication summary and health recommendation requests
  are answered by Claude only when Gemini returns a 5xx or 429, fails to connect, or
  times out mid-request. Gemini answers and other Gemini errors are unchanged, and a
  failed Claude attempt returns the original error (PR #142, decision log 2026-11-24).
  The data-use guide now names Anthropic Claude for that case. On the production server
  a Gemini stand-in returning 503, 429 or no answer was served by Claude, and a 400 was
  not.
- **Final assets:** rebuilt from `56ca41aa` (PR #142 merge), which production also runs.
  The arm64 APK was installed over 1.0.1 on the phone with data kept; the settings screen
  shows `v1.0.1` and both guide sections show the Claude wording. The `v1.0.1` tag was
  moved to the merge of this record, whose app and server code equal the build commit.
