# MedBuddy v0.2.0-beta Development Candidate

## Status

- Candidate version: `0.2.0+21`
- Stable baseline: `v0.1.1-beta`
- Preparation branch: `beta/v0.2.0`
- Target tag: `v0.2.0-beta`
- Platform: Android
- Publication status: active development, not yet published

This document records the current candidate boundary. It is not a release
announcement. Final commit identifiers, signed artifact checksums, deployment
evidence, and deferred-test status must be added only after the release gates
are complete.

## Included Development Scope

- Direct medication entry with schedule review and optional app-owned images.
- Bounded multi-pill identification with explicit per-pill confirmation,
  partial-failure recovery, and duplicate schedule handling.
- Nearby-pharmacy lookup from the home screen with backend-held credentials, map and
  list synchronization, named markers, content-sized collapsible map details,
  favorites, freshness status, and safe external routes. Detail-sheet actions
  preserve map exploration and access to the pharmacy list.
- Patient-caregiver medication chat with active-link navigation, authorized medication and
  pharmacy context, idempotent messaging, read state, and schedule actions.
- Selected chat deletion: private deletion at any age, or sender-only shared
  redaction within 24 hours, without modifying medication records.
- All completed v0.1.1 medication, reminder, caregiver, camera, privacy,
  authentication, accessibility, and HTTPS hardening retained as the baseline.

## Remaining Release Gates

- Pharmacy is available from home and chat is shown for active links. Complete
  their privacy, authorization, and two-device checks before public release;
  navigation visibility is not an authorization boundary.
- Validate the single Alembic head against clean and upgraded PostgreSQL data,
  then deploy the matching backend revision and seed required catalogs.
- Pass backend tests, Flutter analysis and tests, Android release compilation,
  dependency/security checks, and release-metadata validation.
- Install the final signed build on physical devices and verify standalone
  HTTPS startup, authentication, core medication flows, update preservation,
  network transitions, caregiver linking, and push delivery.
- Publish the tag, release notes, artifacts, and checksums only after those
  gates have evidence tied to the final `main` commit.

## Merge Discipline

The preparation branch contains the completed `main` history through the
v0.1.1 baseline as normal Git ancestry. Continue v0.2 work on
`beta/v0.2.0`; do not rebase or force-push the shared branch, and do not merge
it into `main` until the candidate is reviewed and the remaining gates pass.
