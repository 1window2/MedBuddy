# MedBuddy 1.0.0 Release Candidate Line

## Status

- Candidate version: `1.0.0+27`
- Stable baseline: `v0.2.5-beta`
- Preparation branch: `beta/v1.0.0`
- Target tag: `v1.0.0`
- Platform: Android
- Publication status: in development; the distribution channel is an owner
  decision (see [the release TODO](../TODO.md))

This document records the candidate boundary. The GitHub release notes carry the
final commit identifiers and signed artifact checksums.

## Scope

The 1.0.0 line finishes what the beta lines left open: the code work, owner
decisions, owner actions and device checks listed at the top of the release TODO.
New features enter only after a scope review.

- Version `1.0.0+27`; the server reports `1.0.0-rc` until the release.
- The signed workflow and its checks allow `beta/v1.0.0` in place of `beta/v0.2.5`
  for test builds. Builds from it keep the off-Play exception (App Check not
  enforced) until the distribution decision.

## Changes (2026-11-07)

- **Yesterday's list after midnight:** with the app left open across midnight, a tap
  on yesterday's list recorded today's dose and removed tonight's reminder of that
  slot. It is now refused: today's list is loaded and the user is asked to tap
  again. Reminder actions pass their own day and are unaffected.
- **Link codes:** two caregivers redeeming two codes of one patient at the same
  moment could pass the per-patient link limit by one. Redemption now locks both
  accounts before it counts. The lock is released with a commit, so an account row
  created by the same first request is kept.
- **Unlink:** locks both participants, so a chat message or caregiver setting
  written at the same moment cannot stay behind on the ended link. It also
  invalidates the patient's unused link codes: a removed caregiver holding another
  code issued before the unlink could otherwise link again without the patient.
- **Nearby pharmacy search:** a per-account daily quota
  (`PHARMACY_SEARCH_DAILY_LIMIT`, 200) keeps one account from spending the shared
  live pharmacy budget.
- **Chat stream and revoked sessions:** an open chat stream re-checks its ID token
  when it revalidates the link, so a revoked session or a disabled account stops
  receiving messages within about a minute instead of at the token's expiry.
- **Push after a password reset:** a device that kept a revoked session stops receiving
  chat previews and caregiver alerts once the owner signs in again on any device.
- **Prescription text:** a line longer than 500 characters is refused before the privacy
  check; one crafted 20,000-character line had stalled the whole server for about 8
  seconds per request. A full-length text now costs about 2 ms.
- **Pill photos:** the 100-scan JPEG limit from v0.2.5 also covers JPEGs with an MPF
  segment (format "MPO"), which had bypassed it. Photos are turned upright from the EXIF
  orientation tag alone; re-encoding the whole EXIF block let a small image with a large
  tag cost seconds of CPU.
- **Quotas:** pharmacy shares that need a live lookup count against the pharmacy
  search quota, and per-IP counters treat an IPv6 address as its /64. The per-IP daily
  count is taken only after sign-in, so unauthenticated requests no longer leave
  day-long counters that could fill the counter store.
- **Signed builds:** a requested API endpoint is shown before the signing approval,
  and the ingress probe compares the API contract header. The signing job downloads
  the pinned Flutter SDK and all packages instead of restoring a cache that ordinary
  push runs write.
- **Start-up checks:** production refuses two spellings of one setting, missing
  revocation or verified-email checks, and the Firebase Auth emulator variable.
- **Slot completion cards:** the server's message id for a slot completion card is
  reserved; a patient message using it had kept the card from being created.
- **Service key in errors:** pharmacy, holiday and emergency-pharmacy lookups no
  longer chain the httpx error, whose text holds the request URL with the key.
- **Korean UI:** English developer text from a failed check (for example a caregiver
  screen given a reply without its data) is replaced by the generic Korean message.
- **Database role:** an opt-in data-only role for the API and catalog jobs, provisioned
  by the migration (see Production Deployment).
- **CI:** Flutter CI runs the Android instrumented tests (home-widget layout and refresh)
  on an API 34 emulator; the release gate requires them with the rest of Flutter CI.
- **Documents:** the user guide and the UML carry the 1.0.0 version and behaviour changes.
- **Consistency:** history dates follow the shared app offset; home and caregiver
  actions use the shared language rule; course-length messages use the shared
  constant; the notification inbox trims the account hash like account deletion.
