## Status

- Version: `0.2.5+26`
- Stable baseline: `v0.2.4-beta`
- Preparation branch: `beta/v0.2.5`
- Target tag: `v0.2.5-beta`
- Platform: Android
- Publication status: published on 2026-11-06 as a limited off-Play GitHub
  pre-release, like v0.2.4, from PR #134; the APK and AAB were built from

## Scope

v0.2.5 makes existing features easier to find and use rather than adding many
new ones: the bottom tab opens the medication history with weekly, monthly and
custom views, the medication cabinet moves under the schedule's top-right
button and home > 약 등록·관리 > 약 관리, registration is one page, feature search
is grouped by category, and hospital search accepts symptoms.

## Review corrections (2026-10-31)

All ten collaborator commits were reviewed. Each bug fix has a test that fails
without it.

- **Department search:** "배가 많이 아파요", "가슴이 아파요" and "아이가 아파요"
  reached dentistry, and "손목 아파요" reached ENT, because a word ending in 이 or 목
  matched a tooth or throat term. These terms now match only at the start of a
  word. Common emergency wording that found nothing now shows emergency medicine
  and the 119 notice, an empty result shows the 119 notice too, and everyday
  phrases such as "머리가 아파요" and "toothache" find a department.
- **As-needed doses in chat:** "taken" with an as-needed medicine selected
  recorded only the scheduled ones, or failed with a misleading message. Nothing
  is recorded now, and the message says where to record the dose.
- **Old chat schedule cards:** a card older than the 90-day history opened an
  error screen; it no longer opens, like the history card.
- **History tab:**
  - a tab left open overnight moves to today on return;
  - a saved correction shows progress instead of a blank body;
  - a hidden tab no longer reloads on every return to the app;
  - a failed external share over 31 days is no longer hidden by the chat notice;
  - calendar days and period tabs work with screen readers.
- **Prescription result:** leaving after everything was saved no longer warns
  that unsaved results will be lost.
- **Touch feedback:** feature search, department and data-use rows show their
  ripple again; a decorated box was painting over it.
- **Feature search:** follows a language change made on top of it.
- **Privacy notice:** the data use page says that a hospital or pharmacy card in
  chat sends the shared place to the map provider.
- **Overhead removed:** a repeated saved-medication request on the history tab, 30
  text layouts per navigation bar build (now 5), regular expressions recompiled
  on every search keystroke, one chunked history reader instead of two, and code
  left over from the cabinet tab (back handling, month navigation, chart
  variants, per-sender card colours, test-only paths).
- **Security:** Pillow 13.0.0 and pypdf 6.21.4 for the user guide tools, which
  close all open Dependabot alerts. Backend and Flutter dependencies have no known
  advisories, and the commits contain no secrets; new screenshots show test accounts only.

## Device test correction (2026-11-01)

The signed `ad9c78a` build on the Galaxy Note10 showed the schedule spinner for
about 4.5 minutes on the first launch after the update. Nothing was lost. The
cause dates from v0.2.0.

- **Cause:** the app and a WorkManager task are separate Flutter engines. When
  both opened the dose store at the same moment, sqflite gave each its own
  connection, and on the one database thread they share, the waiting statement
  held back the other engine's COMMIT. A two-engine test app reproduced this on
  an emulator: 4 of 4 launches failed an open with `database is locked`, and
  with an existing database each engine finished 1 or 2 transactions in 8
  seconds. The wait is 2.5 seconds there and was 130 seconds on the phone.
- **Fix:** the engines now open the store one at a time, so they share one
  connection and sqflite queues their transactions. The same test app ran 7 of 7
  launches with one connection, no errors, about 150 transactions per engine and
  a longest transaction of 61 ms.
- **Schedule:** a device store that does not answer within 5 seconds no longer
  holds back the schedule from the server.

## Large text (2026-11-04)

The patient and caregiver screens were checked on an emulator at the medium and
large text sizes.

- **Korean wraps by word.** Lines used to break inside words, often leaving one
  syllable alone: "관리해 / 요", "운영시 / 간을", "식 / 후", "875/125밀 / 리그램".
  Descriptions, home cards, page headers, choice sheets, settings summaries, the
  inbox, chat messages and medication names now break only at spaces. A word
  longer than the line still breaks. Screen readers, search and copied text use
  the original text, and date ranges such as "2026-11-04 ~ 11-17" stay on one
  line.
- **Chat + menu as a list.** The menu was a narrow box in the middle of the
  sheet, and at the large size its labels broke inside words. It is now a
  full-width list with one choice per line, like the message menu. The project
  owner chose this layout over a full-width row of icons.
- The two guide screenshots of the menu were retaken, and the PDF was rebuilt.

## 1.0.0 readiness review (2026-11-04)

The branch was reviewed for a 1.0.0 release: the backend for authorization,
input checks, logs and midnight handling, and the app for stale screens,
midnight, disposal and personal data in logs. Authorization, logs, error
responses and disposal were clean. The defects found and fixed:

- **History tab out of date:** with the history tab showing, a dose recorded on
  a schedule screen opened from a notification did not appear when the user came
  back; only the refresh button showed it. The tab now reads again once the server
  has accepted a dose (from the dose queue or an as-needed record). A dose that
  arrives while a read, an editor or the share dialog is open is read after it.
- **Course length of 0 or less:** a direct API call could save or change a
  medication with "0", "0일" or "-7일" days, which became a course that never ends.
  Saving and changing now refuse a length that names a number but gives no day.
  A blank length still means "unknown", as before. The app already sends only 1
  to 3650.
- **Dose time at the edge of the calendar:** an actual dose time such as
  `0001-01-01T00:00:00+14:00` ended in a server error 500. It is now refused with
  the usual range message.
- **Reminders after sign-out:** a 12-hour reminder task already running when the
  user signed out could set the old account's reminders again. The task now
  checks before and after each reminder that the account still owns the device's
  reminders, and removes a reminder it has just set if not.
- **Snooze across midnight:** a reminder snoozed at 23:58 keeps its day. A
  reminder refresh between midnight and 00:08 removed it as stale, so it never
  came. Reminders of an earlier day are now left to fire.
- **Reminder tapped after midnight:** "taken" on yesterday's reminder said to
  check today's schedule. Doing that recorded today's dose of the same time and
  removed tonight's reminder. The message now names the reminder's day and points
  to the history, where that day can be corrected.
- **Dependencies:** pydantic 2.14.2 (the two advisories against 2.13.5 did not
  apply to the backend).

Refactoring without behaviour change: the prescription preview's OCR region
matching moved out of `InputPrescription` into its own file with direct tests,
and the as-needed card uses the shared slot header strip.

## Review of the 2026-11-04 and 11-05 commits (2026-11-06)

The readiness fixes and the collaborator's login logo and guide commits were
reviewed again. The defects found and fixed:

- **Old reminders after a reboot:** the snooze fix above kept every pending
  reminder of an earlier day. Android drops the alarms of a force-stopped app
  while the notification plugin keeps listing them, and the plugin re-arms every
  listed one at the next reboot or app update, so those old reminders would all
  fire at once. Only yesterday's reminder in the first hour of the day, which can
  still be a snooze, is now kept; older ones are cancelled again.
- **Snooze on yesterday's reminder:** "10 minutes later" on a reminder of an
  earlier day said nothing was recorded. It now says the reminder was not
  snoozed.
- **Chat + menu while loading:** before the medicines or today's times arrived,
  the disabled choices said "no active medications" or "no times to check
  today". They now say they are loading, or that loading failed.
- **History tab after a store error:** a dose the server accepted just before a
  device store error did not tell the history tab to read again.
- **Button names:** the empty cabinet and the health recommendation screen still
  offered "약 등록·식별", a menu that the home screen now calls "약 등록·관리".
  The button opens the same flow as "약 등록" in that menu and is now named so.
- **User guide:** 5.1-3 and 5.3-1 explained the "1" beside a deleted message as
  unread; the server never marks a message deleted for everyone as read, so the
  "1" stays. 7.6-5 named the wrong button for leaving selection mode. The build
  record listed 2 changed pages where 10 had changed.

Cleanup without behaviour change, after a reachability check of every app,
backend, Android and guide file:

- Removed 55 guide screenshots that no step uses, the `pdf-images.json` manifest
  and the guide build step that took screenshots back out of the previous PDF
  (no step used it since 20559c2). The guide no longer needs the old PDF to
  rebuild.
- Removed the reminder registration's `medicationNames` and
  `medicationNamesByDate` parameters. Reminders have used neutral text without
  names since v0.2.3, and the values were dropped at the notification service;
  callers no longer build them.
- Removed three unused setting strings, an unused medication getter, an empty
  `docs/images/` folder and the `ios/Runner/Info.plist` fragment (no iOS project
  exists; its permission texts are noted in the Beta Scope).
- Re-rendered `OverallSystemSequenceDiagram.png`, whose text had changed on
  2026-11-04.

## Security audit (2026-11-06)

A source-and-local audit with Cloudflare's security-audit skill: reconnaissance,
coverage-led hunting with a coverage critic, and an independent verifier that tried
to refute every candidate, then a second verifier for each kept record. Local checks
ran in a sandbox without network, against dummy data; the device check used an
emulator and a local backend. No production endpoint was probed. Records are kept
outside the repository (`~/security-audit-skill/MedBuddy/run-1`).

Confirmed and fixed:

- **Another app could record a dose (medium).** Android delivers a tap on a
  reminder's "taken" button to the exported launcher activity, and any installed app
  can start that activity with the same action and extras. On an emulator a probe app
  without permissions marked a slot as taken for the signed-in patient; the server
  then sent caregivers a "completed" alert and suppressed the missed-dose alert.
  Reminder payloads are now signed with a key only the app can read, bound to the
  account, and "taken" or "remind in 10 minutes" runs only when the signature
  matches; otherwise the schedule just opens. Reminders scheduled by an earlier build
  carry no signature, so their buttons open the schedule until the app re-arms them.
- **A crafted photo could stall pill identification (medium).** A progressive JPEG
  re-decodes the whole image for every scan, and a few bytes buy a scan, so one small
  upload could take minutes of CPU and keep one of the four shared analysis slots
  after its own request had timed out. JPEGs with more than 100 scans are now refused
  before decoding.

Hardened, from the same audit (no confirmed exposure):

- Pharmacy location lookups (live fallback and chat pharmacy shares) now share a
  daily budget like the hospital API (`PHARMACY_API_DAILY_REQUEST_BUDGET`, 800).
- At most 12 pill uploads per process are read and analysed at once; more get 503
  with `Retry-After` before the photo is read into memory.
- Compose pins `FIREBASE_CHECK_REVOKED_TOKENS` and `FIREBASE_REQUIRE_VERIFIED_EMAIL`
  to true (production already had both), limits WebSocket messages to 64 KiB at the
  server (`--ws-max-size`), and runs the healthcheck with `python -I`.

Left for the owner (see `docs/TODO.md`): the unused repository secrets, the
data.go.kr quotas behind the MFDS and pharmacy lookups, and host settings.
