# MedBuddy v0.2.1-beta Maintenance Candidate

## Status

- Candidate version: `0.2.1+22`
- Stable baseline: `v0.2.0-beta`
- Preparation branch: `beta/v0.2.1`
- Target tag: `v0.2.1-beta`
- Platform: Android
- Publication status: in development; distributed, like v0.2.0, as a limited
  off-Play GitHub pre-release when ready

This document records the candidate boundary. The GitHub pre-release notes
carry the final commit identifiers and signed artifact checksums.

## Scope

v0.2.1 is a maintenance line: corrections and small improvements to the
v0.2.0 feature set. New features, integrations, migrations and user workflows
need an explicit scope decision first.

Changes so far:

- `workmanager` 0.10.10, which fixes background tasks failing on Android 16
  when the Dart isolate boots slowly, and `image` 4.10.1, which fixes a JPEG
  decoding failure and a WebP decode crash. The other proposed dependency
  updates carried no security fix and were not taken.
- Repository cleanup: superseded validation records, archived coursework
  documents and the bundled user-guide PDF were removed from the source tree.
  They remain in Git history, and published release notes remain on GitHub.
- The directly installable APK now contains only the `arm64-v8a` and
  `armeabi-v7a` native libraries and measures 112.8 MB in CI (v0.2.0:
  175 MB). It no longer installs on x86_64 emulators, which need a local
  build. The Play AAB is unchanged. CI and the signing workflow fail when the
  APK holds any other ABI or an ABI without the Flutter engine.
- Android manifest entries without any remaining use were removed: the legacy
  storage permissions (`READ_EXTERNAL_STORAGE`, `READ_MEDIA_IMAGES`), a map-app
  query and an unused widget broadcast receiver. Photo selection uses the
  system picker and needs no storage permission.
- All app data is excluded from cloud backup and device-to-device transfer on
  Android 12 and later, so the encrypted dose store cannot arrive on another
  phone without its device-bound key. This was not verified between two
  physical phones.
- Per-user request limits and the release of the account lock before public
  medication lookups take effect again. Neither was in effect in v0.2.0 on
  the medication, pharmacy, hospital and chat routes; per-IP limits were not
  affected. Link-code issue (10 per hour) and link registration (5 per five
  minutes) are enforced per user for the first time.
- Backend corrections: a failed or empty AI summary or health answer is no
  longer stored, cached or served; the database connection is released before
  every push send; a slow holiday lookup still fills its cache; caregiver
  settings stored in the legacy shape produce alerts as the settings screen
  shows them; recording a slot and the missed-dose tick run a fixed number of
  queries; the Redis detail cache recovers by itself after an outage.
  Combination strengths are compared per component and an ambiguous name
  prefix ends as unverified.
- Client corrections: the on-device privacy filter masks patient names in
  label layouts it previously missed and never masks a dose row; a transient
  token-refresh failure keeps the session while a rejected identity ends it;
  a dose tapped right after midnight is recorded for the new day; the
  12-hour worker does not re-arm a reminder for a slot already taken; a
  failed push start is retried; a failed load of the medication box is shown
  as an error instead of an empty box; timeouts and offline errors show
  localized guidance; dose recording from chat uses the same offline queue as
  the schedule; a dose store whose device key is gone recovers and reports
  the lost records.
- Behaviour that changes for users: a totally failed AI summary is an error
  with retry instead of "요약 실패" fields; an over-long AI field is shown
  shortened with "…"; nearby searches accept dates from seven days back to
  366 days ahead; an overnight late-night pharmacy designation stays official
  after midnight; the home-screen widget no longer fetches other-device
  changes every 15 minutes while it has today's data.
- Reviewed and deliberately not included: ranking of fuzzy catalogue
  candidates (it would let more model-chosen names pass without user review;
  needs a check on the production catalogue) and delivering WebSocket close
  codes after accepting the handshake (released clients would reconnect every
  second). Both are tracked in [the release TODO](../TODO.md).
- Pipeline: CI caches Gradle and cancels only pull-request runs superseded by a
  newer push (push runs, which the release gate reads, are never cancelled);
  new tests pin the structure of the CI and signing workflows and the
  Dart–Kotlin widget contract; the configuration check rejects the off-Play
  App Check exception on every ref except `beta/v0.2.1`.

## Release Gates

- The signed-build workflow requires successful `push` runs of both
  `backend-ci.yml` and `frontend-ci.yml` for its exact source commit. Wait for
  CI to finish before dispatching it; do not bypass this gate.
- Firebase App Check stays disabled under the off-Play exception, which the
  workflow allows only on `beta/v0.2.1`. Signed builds from `main` require App
  Check, so the directly installable APK is built from the final commit of the
  preparation branch, whose tree must equal the merge commit that is tagged.
  The AAB is always built with App Check enabled and is not usable until Play
  distribution and enforcement are set up.
- Install the final signed build on a physical device as a replace-only update
  and verify startup without credential entry, preserved medications and
  notification history, core schedule actions and dose synchronization. Because
  manifest entries were removed, also pick a medication photo from the gallery
  and record a dose from the home-screen widget.
- Deploy the matching backend revision before distributing a client that
  depends on it, following [the deployment guide](../Production%20Deployment.md).
  Before deploying, count the caregiver settings stored in the legacy shape
  (`SELECT count(*) FROM guardian_alert_settings WHERE slot_settings='{}' AND
  enabled`): those caregivers start receiving missed-dose pushes. After
  deploying, check link-code issue and link registration from a device, and
  run a few real prescriptions through the analysis.
- This line changes the dose queue, reminders, the widget worker, the session
  gate and the privacy filter. None of it has been exercised on a device yet;
  the device items are listed in [the release TODO](../TODO.md).
- Open acceptance items and known limits carried over from v0.2.0 are tracked
  in [the release TODO](../TODO.md). State in the release notes which of them
  were verified.

## Merge Discipline

Work on `beta/v0.2.1`; do not rebase or force-push the shared branch. Merge
into `main` with a merge commit when the owner decides to publish.
