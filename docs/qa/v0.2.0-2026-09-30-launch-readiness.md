## Priority findings and corrections

1. **Public ingress blocks shipped features and signing readiness.** Read-only
   public probes returned HTTP 200 for `/ready` but HTML HTTP 403 for
   `/ready/catalogs` and `/api/v1/hospitals/nearby`. The deployment allowlist also
   omitted these paths. The runbook now includes them, and signing checks the
   pharmacy, hospital and chat routes reach JSON authentication denials before
   restoring Firebase/keystore material. Probes use no credentials and perform
   no authenticated search or user write. The live Cloudflare rule still needs
   an authorized operational update; repository changes alone do not fix it.
2. **Pharmacy calendar outages could claim weekday opening.** The controller
   previously retained `False` after calendar lookup failed, selecting normal
   weekly hours. It now distinguishes unknown status for each date, bounds
   calendar waits, removes unverified intervals and keeps unrestricted location
   results available. Verified current-day or previous-day overnight intervals
   can still prove opening independently. Time-filtered empty results and source
   notes explain the missing verification. Official designations remain separate
   from actual opening status. No public response fields or schema change.
3. **Release scope lagged implemented hospital/chat work.** The scope and candidate
   notes now include hospital search/sharing, unread boundaries/read receipts,
   notification routing and durable chat delivery. The obsolete statement that
   nearby care/chat were hidden in laboratory settings has been removed.

The runtime correction follows the existing nearby-care use cases and calendar
boundary. Calendar session isolation, pure time/distance policy, active-link
authorization, provider budgets and the migration chain remain intact.
