# Patient and caregiver schedule time labels

Baseline: `78675c9`, `beta/v0.2.0`.

The meeting's 02:38-versus-08:00 discrepancy came from unlike display sources:
the patient header used the enabled reminder time, but the caregiver header
always used the slot's product-default hour. Neither represents an authoritative
prescription-specific administration time.

Headers now identify their actual meaning:

- Patient: `Reminder <time>` / `복약 알림 <time>`, or reminder off.
- Caregiver: missed-dose alert time, alert on completion, or alerts off.
- Missing/invalid caregiver settings show an unavailable/loading state, never
  a fabricated fallback time. Global notification preferences are respected.
- Chat medication-selection mode does not claim an alarm time from synthetic
  slot defaults.

Morning/lunch/evening/bedtime remain schedule categories. Patient reminders and
caregiver deadlines remain independent; the caregiver API does not provide the
patient's alarm settings, so the UI must not infer them. This display-only fix
does not alter prescriptions, persisted alarm times, notification delivery,
completion records, or account permissions. Existing UserSetting clock-format
conversion is retained. No new architectural layer or API contract is added.

Regression coverage includes the reported 02:38 reminder, disabled reminders,
all caregiver modes in Korean/English and 12h/24h formats, and 2x text layouts.
Tests run in an isolated Flutter 3.41.5 copy with the committed dependencies;
the unrelated local lockfile modifications are preserved and excluded.
Full verification: **978 Flutter tests passed**, static analysis found **no
issues**, and `git diff --check` passed.
