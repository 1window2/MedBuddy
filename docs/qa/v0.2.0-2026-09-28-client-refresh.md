# 조회·알림·위젯·사진 처리 개선 검증

기준: `2f1e93d`, `beta/v0.2.0`. 해당 커밋 이후 개선 작업본을 검사했다.
아래 수치는 로컬 데모 환경의 관찰값이며 전체 앱의 성능 측정 결과는 아니다.

## 자동 검증

- 전체 Flutter 테스트 1,050개 통과.
- 보호자 통합 조회 및 인증·권한 관련 서버 테스트 40개 통과.
- Flutter 정적 분석과 변경분 공백 검사 통과.
- 변경한 UML 7개 문법 검사 및 다이어그램 이미지 재생성 완료.

| 영역 | 회귀 검증 |
| --- | --- |
| 보호자 조회 | 알림을 끈 환자 포함, 약 상세 제외, 인증된 보호자 범위, 동시 조회 공유와 세션 격리 |
| 채팅 | 정상 연결 중 조회 중지, 장애 보완 조회, 재연결 반복 시 주기 유지, 50개 초과 누락 복구 |
| 일정·알림 | 짧은 탭 재방문 재사용, 직접 새로고침, 상태 변경 무효화, 동일 예약·미루기 보존 |
| 복용 기록·위젯 | 표시 콜백 지연 중에도 영속 저장·전송, 늦은 홈 설정 복원 후 환자 조회 |
| 사진 | 직접 등록 이미지 저장·축소, 기존 처방전 자르기·원본 정리 규칙 |

## 환자·보호자 에뮬레이터

두 Android 에뮬레이터에 개선 작업본을 설치하고 다음을 확인했다.

1. 보호자 홈에서 연결된 환자 두 명을 전환하고 진행률을 표시했다. 32초 관찰 중
   일정 일괄 조회는 2회였으며 환자별 약 상세 요청은 없었다. 기존 연결 목록과
   알림 감시 요청까지 모두 제거한 것은 아니다.
2. 환자가 복용 완료하면 다음 시간대로 이동하고, 보호자 홈과 두 위젯의 진행률이
   일치했다. 위젯에서 복용 취소한 결과도 반영되었다.
3. 네트워크 단절 중 복용 기록은 기기에 저장되어 전송 대기를 표시했다. 연결을
   복구하자 서버·보호자 화면·위젯에 반영되었다.
4. 홈과 일정 탭을 빠르게 다섯 번 왕복했을 때 일정·알림 설정 재조회는 0회였고
   저장된 알림 예약 계획도 바뀌지 않았다.
5. 양방향 채팅 수신을 확인했다. 정상 연결 26초 동안 이력 반복 조회는 0회였다.
   백그라운드 복귀 후 누락 메시지가 표시되었고, 소켓 연결만 차단한 상태에서는
   HTTP 보완 조회로 메시지를 받았다. 재연결 후 메시지 중복은 없었다.
6. 3600×2700 시험 이미지를 직접 등록해 1600×1200 JPEG로 저장한 뒤 복약함과
   일정에서 썸네일을 확인했다. 저장 파일 크기는 137,409바이트였다.
7. 가상 카메라 촬영 결과에서 620×414 가이드 영역 이미지와 임시 원본 삭제를
   확인했다. 처방전 글자가 없는 장면은 인식 실패로 안내되고 홈으로 복귀했다.

## 기기 검증 중 추가 수정

- 보호자 홈 설정이 비동기로 늦게 복원되면 화면과 내부 조회 출처가 달라져
  위젯 환자 정보 갱신이 누락될 수 있었다. 부분 갱신에서도 출처를 동기화하고
  출처 변경 시 기존 발행 비교값을 초기화했다.
- 채팅 재연결 시도마다 보완 조회 타이머를 다시 만들면 실제 조회가 계속 미뤄질
  수 있었다. 이미 동작 중인 타이머는 유지하고 정상 연결·백그라운드에서만 중지한다.

두 문제 모두 실패를 재현하는 회귀 테스트를 추가한 뒤 수정하고 전체 Flutter
테스트를 다시 실행했다.

## 범위와 한계

시험 약과 시험 메시지는 기존 삭제 경로로 정리했다. 앱 데이터 초기화 없이
환자·보호자 데모를 유지하고 임시 장애 재현용 연결도 원래대로 복구했다.

운영 Firebase 푸시, 제조사별 실기기, PostgreSQL 부하, 실제 처방전 OCR 정확도는
이번 검증 범위가 아니다. 프레임 지연·메모리·응답 시간의 전후 비교 측정도 하지
않았으므로 특정 배수의 속도 향상을 주장하지 않는다. 서버 관련 테스트에서
기존 Starlette/httpx 사용 중단 예고 경고가 남았으며 실패는 아니다.
