# v0.2.0 architecture and next gates

Review baseline: `8b58da3`, 2026-09-10. This is a focused review of critical
flows, not a claim that every failure mode has been eliminated.

## Architecture assessment

The Boundary-Control-Entity structure is suitable for continuing controlled
beta testing on the current single API process. Authenticated HTTP, local OCR,
catalog lookup, persistence, and notification transport have separate adapters.
UI visibility never substitutes for backend authorization.

| Path | Reviewed protection | Limit / remaining evidence |
| --- | --- | --- |
| Authentication | Same-origin bearer delivery, verified principal, active caregiver scope, account-operation locking | Off-Play App Check exception remains a public-release blocker in `docs/TODO.md`. |
| Prescription | On-device redaction, bounded HTTP request, operation invalidation, capture cleanup after OCR | Cancellation must also suppress upload when OCR finishes after exit. Physical camera/OCR quality still needs sample evidence. |
| Dose completion | Patient-scoped whole-slot transaction and transactional outbox | Delayed notification actions must carry their original date; server rejects date mismatch with 409 before writes. |
| Caregiver delivery | Unique event key, atomic claim, retry backoff, dead-letter limit, link/preference/live-state recheck | FCM delivery is at least once: a crash after sending or partial multicast success can cause repeats. A unique outbox row does not guarantee exactly-once receipt. Two-device tests remain required. |
| Pharmacy / pill lookup | Backend-only public-data keys, bounded image processing, candidate confirmation, catalog-backed results | Pharmacy hours need freshness/telephone confirmation. Recognition accuracy needs an independently labelled photo corpus. |
| Chat | Active-link authorization and scoped persistence/deletion | WebSocket membership is process-local. Horizontal scaling needs shared event fan-out; two-device reconnect/deletion tests remain open. |

## Corrections from this review

- Register prescription cancellation before local OCR begins. After OCR,
  cancelled/disposed flows must terminate before starting an HTTP upload.
  Keep app-owned capture deletion deferred until OCR releases the file.
- Include the dose day in newly scheduled notification payloads. Reject
  undated legacy, expired, and future quick actions; ordinary reminder
  navigation remains supported for legacy payloads.
- Send `expected_schedule_date` with notification completion. The
  backend rejects a mismatch with its application calendar before modifying
  medication or outbox rows. Existing callers without this optional field
  retain their current API behavior.
- Preserve the original dose date through snooze, including a snooze that fires
  after midnight. It must not become permission to complete the next day's dose.
- Update the release scope to reflect promoted pharmacy and active-link chat.

## Gate order

1. Regression checks: cancellation during OCR/disposal; stale/undated/future
   notification no-write behavior; matching-date completion; date propagation;
   current backend and Flutter CI.
2. Signed build and physical-device checks: in-place update, session/data
   preservation, freshly dated reminders, stale-action rejection, foreground
   and background recovery. Use a designated test account and test doses for
   completion writes; never infer that the user's real medication was taken.
3. Real-photo prescription/pill tests with known expected results, without
   saving uncertain identities as medication schedules.
4. Two linked devices: completion/missed-dose delivery, consent changes,
   retry/duplicate behavior, chat deletion and reconnect.
5. Play Integrity / App Check release requirements, final review, then the
   documented normal merge and publication gates.

Passing CI permits the next testing gate; it does not satisfy the outstanding
physical, recognition-quality, or public-release requirements by itself.

## Bulk completion correction

Whole-slot completion Undo in `frontend/lib/main.dart` and
`frontend/lib/views/home_screen.dart` previously sent a whole-slot `false`
update instead of restoring previous per-medication states. A partly complete
slot could lose earlier records. Both shortcuts now offer **Review schedule**:
navigation performs no completion write, and individual corrections remain
available in the schedule. Regression tests cover both entry points and verify
that review does not send a bulk reset.

Any future genuine Undo needs server-validated, date-bound restoration of only
the original operation's changes, with concurrent-update checks. The explicitly
labelled schedule action to cancel an entire slot is distinct from Undo and is
not a restoration operation. Completion acceptance still needs designated test
doses rather than real patient records. The assessment is not blanket release
approval.

## Reminder snapshot safety

Scheduled notification text is not a live view of completion state. Commit
`a90f146` uses neutral schedule/completion-record wording for regular and
snoozed reminders, regardless of privacy settings. It never presents stored
medication names as doses currently due. Android channel regression coverage
includes stale name lists, both languages, and snooze fallback/date retention.
Previously stored alarms require a successful online refresh after updating.
See the dated validation report for CI and physical evidence; this correction
does not close the remaining device, recognition, or public-release gates.

## Refactoring audit, 2026-10-02–03

Starting baseline: `13a0670`, `beta/v0.2.0`. Reviewed backend control/boundary
dependencies, frontend library reachability and feature responsibilities, and
release/deployment script wiring. The existing BCE design remains the organizing
structure; stateless protocol utilities do not need artificial inheritance.
Before completion, fast-forwarded to `043843f` and reconciled all four incoming
commits. Original strength/form rejection, explicit medication candidate review
and owner/date-bound widget reminder cancellation are preserved.

- Extract `PrescriptionMedicationNameVerifier` and its verification value from
  `InputPrescription`. The control coordinates privacy-safe OCR analysis; the
  reusable service owns bounded catalog matching and catalog-constrained AI
  fallback. Worker-owned catalog sessions and confidence/privacy rules remain
  unchanged. The control shrinks from 1,364 to 349 lines.
- Move notification destination/action values into a platform-neutral entity and
  parsing/action identifiers into `MedicationNotificationPayloadCodec`.
  `NotificationService` keeps scheduling, plugin lifecycle and its existing API.
  Original dose dates, recipient validation and legacy navigation remain intact.
  Malformed URL encoding in legacy caregiver payloads now returns no selection
  instead of throwing; versioned payload rejection is also regression-tested.
- Encapsulate process-local SQLite account locks in `AccountOperationLocks`.
  One context owns acquisition, timeout, holder/waiter reference counts and
  teardown, fixing leaked registry references on cancelled waits. PostgreSQL
  advisory locking and account-deletion retry/error contracts remain unchanged.
- Centralize sequential request-session worker lifetime in
  `run_request_database_work`. Health authorization, medication/cache reads and
  cache writes no longer block the event loop. Account registration and async
  chat database phases use the same cancellation-draining adapter so direct,
  repeated and queued-capacity cancellation cannot race session cleanup. The
  intentional PostgreSQL account-deletion transaction remains held during the
  LLM wait. Cancellation is not a rollback of an already committed operation.
- Replace embedded Android workflow validators with immutable release-policy,
  backend-identity and Firebase-client expectations in
  `scripts/check_android_release_configuration.py`. The workflow only
  orchestrates checks, remote probes and signing; protected environments,
  App Check requirements and artifact-channel rules are unchanged.
- Remove the retired 488-line `CheckTodayMedicationInfoUI` module after proving
  no production import, export, route or platform registration references it.
  Migrate its two regression cases to the active `HomeMedicationPreview` /
  `HomeMedicationSlotPager` composition, including compact doubled-text checks.
  Every remaining frontend library is reachable from `main.dart`. Historical
  documentation, ORM metadata-registration imports, migrations and intentionally
  dormant deployment workflows are not unused source and are retained.
- Keep another row's technical lookup error visible when a medication candidate
  is confirmed. Only resolving all unverified rows clears that aggregate error;
  retry recovery, new recognition and reset retain their existing semantics.

Dependency guards prevent prescription verification from importing API/control
or configuration orchestration, keep the notification protocol free of platform
plugins, and keep local release-policy/account-lock utilities standard-library
only. Validate Flutter against pinned 3.41.5 with `--enforce-lockfile` in an
isolated copy; neither the tracked lockfile nor the global SDK is changed.

Final local verification on 2026-10-03: 1,053 backend tests passed, two
PostgreSQL catalog integration tests skipped without a configured test database,
and six existing dependency deprecation warnings. Pinned Flutter analysis found
no issues and all 1,231 tests passed, including compact/large-text UI and the
incoming matching/widget regressions. All 166 frontend libraries are reachable
from `main.dart`. Six workflow YAML files and 35 Bash steps parse successfully;
the five changed UML sources pass syntax validation and their PNGs are regenerated.
These results do not substitute for real PostgreSQL concurrency, signed release
execution or the deferred physical-device checks.

Further bounded opportunities remain: give linked-chat history/retry/read state
an independent owner, separate the medication-detail control's embedded helpers,
and remove pharmacy-specific naming/inheritance from shared nearby-care/GPS
contracts. Do not remove reachable code or add base classes merely to reduce
line counts. Physical-device, recognition-quality and public-release gates above
remain open; Google Play account enrollment is deferred at the owner's request.

## Follow-up refactoring audit, 2026-10-03

Baseline: `ffd2487`, existing `beta/v0.2.0`; the initial fast-forward pull was
already up to date. This pass addresses remaining concrete ownership weaknesses,
not arbitrary file-size reduction or blanket launch approval.

- Extract medication-name normalization/ranking, Redis cache, approval-document
  summary generation and local catalog lookup into four cohesive public modules.
  `CheckMedicationDetail` shrinks from 1,556 to 316 lines and keeps use-case
  coordination and original-evidence validation. AST comparison and existing
  regressions preserve matching, cache/AI behavior and response contracts.
- Fix optional approval-summary persistence: detached catalog rows previously
  changed only in memory before a commit on the unrelated request session.
  Independent Engine-bound workers now commit only the four summary fields with
  an atomic original-product/document check. Catalog refresh/deletion rejects
  stale writes; failures return generated guidance without exposing exception
  payloads. Worker cancellation/connection-return tests prove request-session
  cleanup cannot race borrowed-session writes. Connection-local in-memory SQLite
  keeps the existing read fallback and skips optional summary persistence rather
  than commit someone else's transaction. This is not real PostgreSQL evidence.
- Make hospital and pharmacy controls siblings under `CheckNearbyCare` and give
  shared UI a provider-neutral control contract. Only pharmacy exposes the 20 km
  list shortcut; hospital search retains its 300 m default and bounded expansion.
  Move WGS84 coordinates out of the pharmacy record library so generic GPS/cache
  services do not depend on a provider. Explicit map areas, fresh GPS resets,
  fallback provenance, holiday uncertainty and caller-owned clients remain intact.
  Disposed searches/area requests cannot start GPS or HTTP, including after a
  pending GPS success/failure. The legacy shared display DTO names remain for now;
  this pass does not change backend wire fields or favorite-storage keys.
- Give `LinkedChatHistoryViewModel` immutable account/link ownership of history
  catch-up, backwards pagination, monotonic receipts/deletion evidence and
  failure-only polling. The identity-keyed presentation session keeps draft,
  navigation and adapter ownership. Account/link/patient changes replace the old
  session; same-conversation updates keep the draft. UI state cannot directly
  mutate the history snapshot, and disposed/wrong-link callbacks are rejected.
- Fix account-lock cancellation at ownership handoff by replacing child-task
  `wait_for` acquisition with inline `asyncio.timeout` acquisition. A deterministic
  real-lock regression fails on the old path and passes after the fix. Holder /
  waiter cleanup, five-second request policy and nonpositive-deadline behavior
  remain unchanged; PostgreSQL advisory locks are not modified.

All 169 frontend libraries are reachable through production imports/exports/parts.
No further source file is proven unnecessary, so no additional deletion is made.
New dependency guards prevent medication collaborator API/control back-edges and
provider-specific imports in generic GPS/nearby ownership. Historical migrations,
ORM registration and intentional deployment workflows are retained.

Final local verification: 1,074 backend tests passed, two PostgreSQL catalog
tests skipped without a configured database, and six existing dependency
deprecation warnings. Pinned Flutter 3.41.5 / Dart 3.11.3 analysis found no issues;
all 1,256 frontend tests passed, including 15 new chat owner/session tests and
ten nearby-care lifecycle/architecture cases. The seven changed UML sources
validate and their PNGs are regenerated locally. Independent reviews found no
blocking regression. The tracked dependency lockfile, app version and global
SDK are unchanged; no live deployment or physical-device gate was executed.

Remaining bounded architecture work includes isolating chat card rendering and
composer/share retry state, replacing pharmacy-named shared display contracts with
explicit nearby-care entities, and reducing large nearby-care presentation helpers.
Physical-device, recognition-quality and public-release gates remain open.
