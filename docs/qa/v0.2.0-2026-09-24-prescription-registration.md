# 처방전 인식부터 복약 등록까지 점검

기준: `f1379ae`, `beta/v0.2.0`. 해당 커밋 이후 작업본을 검사했다.

## 발견한 문제와 수정

### 복용 횟수와 실제 시간대 불일치

OCR 검토 창에서 1일 횟수만 고치거나 누락된 약을 추가하면, 화면의 횟수와
실제 저장되는 시간대가 달라질 수 있었다. 예를 들어 누락된 약에 3회를 입력해도
초기 선택인 아침만 저장됐다. 시간대를 직접 바꿀 때도 횟수는 이전 값으로 남았다.

- 횟수를 바꾸면 기존 공통 규칙에 따라 해당 개수의 시간대를 선택한다.
- 시간대를 직접 선택하면 횟수도 선택 개수로 갱신한다.
- 횟수가 같거나 용량만 수정한 경우에는 사용자가 고른 시간대를 유지한다.
- 편집한 횟수가 비어 있거나 1~4회 범위를 벗어나면 수정 적용 전에 안내한다.
- 기존 시간대 결정 규칙 자체는 바꾸지 않았다. 자동 선택된 시간대도 검토 후 수정할 수 있다.

추가한 횟수별 회귀 테스트 4개가 수정 전 실패했고 수정 후 통과했다.
기존 누락 약 추가 테스트에도 실제 시간대 검증을 보강했다.

### 일정 조회 실패를 빈 일정으로 처리

HTTP 상태가 200이더라도 실패 표시가 있거나 목록이 없는 응답을 일정 없음으로
처리했다. 저장 직후 이런 응답이 오면 약이 정상 등록됐는데도 일정이 없는 것처럼 보일 수 있었다.

오늘 일정·일정 요약·알림 조회 기간의 응답을 검증하고 실패 상태로 전달하도록 수정했다.
정상 빈 목록과 요약 응답의 `schedules`/기존 `schedule` 형식은 계속 허용한다.
저장 완료 여부와 조회 실패를 분리하며 재조회로 복구한다.

## 자동 검증 범위

| 단계 | 확인한 내용 |
| --- | --- |
| 촬영·파일 처리 | 촬영 파일 입력, 갤러리 원본 보존, 취소·화면 종료, 진행 중 OCR 완료 후 임시 파일 정리, 회전·촬영 영역 계산 |
| 인식·개인정보 | 비식별 텍스트 전송, 개인정보 마스킹 영역, 빈 입력·과대 입력·인식 실패·시간 초과, 분석 취소 |
| 약품 검토 | 약명·용량·횟수·기간·시작일 수정, 누락 약 추가, 검증 완료 행 잠금, 작은 화면·큰 글씨 |
| 횟수·시간대 | 1~4회 변경, 직접 시간대 선택, 기존 선택 유지, 잘못된 횟수 거부 |
| 저장 | 개별 저장 후 전체 저장, 반복 저장, 부분 실패·전체 실패 후 재시도, 서버 저장 후 응답 유실 |
| 복약함·오늘 일정 | 시작일·용량·기간·시간대 유지, 정상 빈 일정과 실패 응답 구분, 저장 후 조회 실패와 복구 |
| 서버 데이터 | 15가지 시간대 조합 × 5가지 시작일·기간 조건, 환자별 격리, 중복 요청, 새 처방이 이전 완료 상태를 물려받지 않음 |

기간 조건은 오늘 시작, 마지막 복용일, 복용 종료 다음 날, 미래 시작,
기간 미상에 대한 기존 정책을 포함한다. 종료일의 당일까지는 오늘 일정에 표시한다.

- 전체 Flutter 테스트 **1,012개 통과**. 이번에 추가한 테스트는 25개다.
- 처방전 파싱·분석·저장·일정 관련 서버 테스트 **150개 통과**. 새 격리 DB 테스트는 76개다.
- Flutter 정적 분석: 문제 없음.
- 환자·보호자 Android 디버그 앱 빌드 및 기존 데이터 유지 설치 성공.

Flutter 저장 흐름 테스트는 실제 ViewModel과 Control을 연결하되 문자 인식 엔진과
HTTP 응답을 대체한다. 서버 테스트는 격리된 메모리 DB를 사용한다.
자동 테스트 숫자는 실제 카메라 촬영 횟수나 서로 다른 실제 처방전 수를 뜻하지 않는다.

## 에뮬레이터 확인

개인정보가 없는 가상 처방전과 기존 데모 계정을 사용했다.

1. 카메라에서 처방전이 아닌 가상 장면을 촬영했다. 인식 실패 안내와 재촬영·사진 다시 선택이 표시됐다.
2. 실패 화면에서 가상 처방전 이미지를 선택했다. 실제 기기 OCR과 데모 서버 분석을 거쳐 약명·1정·1회·5일·시작일이 표시됐다.
3. 검토 창에서 횟수를 3회로 바꾸자 아침·점심·저녁이 함께 선택됐다.
4. 약품 분석 후 전체 저장으로 한 건을 등록했다. 복약함의 등록일과 복용 기간이 구분되어 표시됐다.
5. 오늘 일정에 세 시간대가 모두 미복용으로 등록됐다. 기존 복용 완료 상태는 유지되고 진행률이 5/5에서 5/8로 바뀌었다.
6. 보호자 홈에서도 연결된 환자의 5/8 진행률과 새 일정을 조회했다.
7. 앱의 삭제 기능으로 이번 시험 약 한 건만 삭제했다. 서버의 약 ID 목록과 기존 시간대별 완료 상태가 시험 전과 동일함을 비교했다.

## 검증 한계

실제 종이 처방전을 카메라로 찍는 성공 경로는 이번에 재현하지 않았다.
에뮬레이터 카메라는 실패 경로를, 가상 처방전 사진 선택은 실제 OCR부터 저장까지의
성공 경로를 확인했다. 다양한 병원 양식, 실제 촬영의 흐림·반사·그림자,
제조사별 카메라·권한 화면, 운영 환경의 장시간 통신 장애는 별도 실기기 검증이 필요하다.

약명 보정·기간 등은 인식 결과를 사용자가 검토한다는 기존 전제를 유지한다.
이번 점검은 실제 처방의 의학적 적절성이나 사용자의 실제 복용 여부를 검증하지 않는다.
