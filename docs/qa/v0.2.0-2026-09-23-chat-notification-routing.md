# Caregiver chat reminder navigation

Baseline: `e7c6db8`, existing `beta/v0.2.0`.

The September 22 meeting reported that tapping a caregiver's chat reminder
opened the patient's schedule instead of chat. Both local notification creation
and FCM tap handling special-cased `slot_check_request` into a `schedule:`
destination, while the inbox already used `chat:<linkId>`.

All linked-chat notification kinds now open their originating conversation.
This is navigation only, with no medication completion write. FCM recipient and
positive-link-ID checks remain unchanged, as do authentication and active-link
authorization in the existing app/chat flow. Cold-start and background FCM taps
share the same handler. Ordinary medication alarms and caregiver missed-dose
actions retain their separate schedule/action routing.

Existing optional message-kind/slot parameters remain accepted by the local
notification API for caller compatibility; they no longer override navigation.
No server contract, chat message content, or dose recording behavior changes.

Regression tests cover all four dose slots and an unknown slot, normal chat,
local notification/inbox agreement, invalid links, wrong recipients, and
navigation without a synthesized dose action. Tests use mocked platform/HTTP
boundaries and the committed lockfile in an isolated Flutter 3.41.5 copy.
The full suite passed **964 tests**; static analysis found **no issues** after
removal of the obsolete chat-to-schedule helper. `git diff --check` passed.

Physical validation remains deferred: send a new caregiver reminder to a
designated patient test account, then tap it with the app foregrounded,
backgrounded and terminated; check the correct conversation and no dose write.
Already-posted local notifications retain their old serialized payload and
cannot recover a missing chat link ID; use newly delivered notifications after
updating. The notification inbox already opens the conversation.
