## Pharmacy resume correction

`b21e0ef` adds lifecycle observation to the pharmacy screen:

- A real background/resume transition refreshes a query at least one minute old,
  one crossing a calendar-day boundary, or one affected by clock rollback.
- Failed location/network lookups are retried on return.
- Brief inactive-only system interruptions and fresh queries avoid extra work.
- An in-flight old request gets at most one queued follow-up rather than a
  concurrent duplicate. Existing search-generation guards still reject obsolete
  responses.
- The current search area, filter, and explicitly chosen calendar date survive.
- The observer is removed on disposal, and covered routes do not auto-refresh.

New deterministic widget regressions exercise short interruptions, stale resume,
duplicate resumed events, disposal, and midnight resume with an in-flight query.

when complete. Signed test workflow: `34662587962`.

### September 13: native Android mismatch discovered

The expired dummy row was guardedly moved to September 13, relabelled
`TEST_ONLY_DO_NOT_TAKE_CANCEL_20260913`, and its deduplication key recomputed using
the application's function. It remained evening-only, one-day, uncompleted, and
unlinked to caregivers. This was test-fixture setup, not a production medication

A 03:03 exact reminder was scheduled and its actual Android notification observed
at 03:03:32. Disabling the slot changed the server setting to disabled, but the
notification remained visible. Morning alarms were unchanged. Thus the physical
recheck of `9cfb42d` **failed**, despite its mocked regression passing.

Inspection of the locked plugin version (`flutter_local_notifications` 22.3.0)
found that Android `getActiveNotifications` returns channel/group metadata but
does not return payload. The original test supplied a field absent on Android.

`a5fdddc` fixes this mismatch:

- New reminders carry a per-slot Android group marker, with no patient identifier.
- Explicit slot cancellation uses channel/group metadata; older ungrouped
  reminders are recognized by deterministic date IDs within a bounded 90-day
  compatibility window. Unidentified older notifications are not broadly cleared.
- Global reminder cancellation and session cleanup also recognize the app's
  corresponding Android channels rather than relying only on payload.
- Regression mocks now omit Android payloads and cover other-slot/channel
  preservation, recent legacy date IDs, and session cleanup.
