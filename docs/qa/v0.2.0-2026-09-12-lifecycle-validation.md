## Pharmacy resume correction

`b21e0ef` adds lifecycle observation to the pharmacy screen:

- A real background/resume transition refreshes a query at least one minute old,
  one crossing a calendar-day boundary, or one affected by clock rollback.
- Failed location/network lookups are retried on return.
- Brief inactive-only system interruptions and fresh queries avoid extra work.
- An in-flight old request gets at most one queued follow-up rather than a
  concurrent duplicate. Existing search-generation guards still reject obsolete
  responses.
- The current search area, filter, and explicitly chosen calendar date survive.
- The observer is removed on disposal, and covered routes do not auto-refresh.

New deterministic widget regressions exercise short interruptions, stale resume,
duplicate resumed events, disposal, and midnight resume with an in-flight query.

when complete. Signed test workflow: `34662587962`.

## Defect discovered during cancellation

Disabling the evening slot successfully disabled its server setting but left
the already-delivered date-specific notification visible. The slot cancellation
path enumerated pending requests only; a delivered reminder is no longer pending.

`9cfb42d` adds active-notification cancellation for the exact slot payload prefix,
including its tag. This runs only on explicit cancellation, not routine schedule
refresh. Its platform-channel regression covers delivered snooze removal while
preserving other slots, chat/caregiver alerts, null payloads, and similar-but-not-
matching slot prefixes. Flutter run `34691510378` passed static analysis and all
Flutter tests; its compile-only Android build was still running when this report
was recorded. FastAPI run `34691510341` passed. The installed APK above does
**not** contain this follow-up fix, so physical revalidation remains pending.
