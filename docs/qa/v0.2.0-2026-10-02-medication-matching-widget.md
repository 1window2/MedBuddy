# 2026-10-02 약명 매칭·위젯 재알림 검증

## 범위

- 원격 `13a0670`의 Android App Check 배포 사전 검사를 반영한 상태에서 확인했다.
- 환자·보호자 Android 에뮬레이터, 로컬 SQLite 백엔드와 테스트용 처방전 이미지를 사용했다.
- 실기기·운영 배포 승인 또는 모든 약품의 임상적 동등성 검증을 의미하지 않는다.

| 후보창 진입·취소·재진입 | 기본 선택 없음, 선택 전 확인 비활성, 취소 시 미확인 유지 |

| 계정 잠금 503 | 묶음 완료 후 해당 요청만 순차 1회 재시도하여 후보 표시까지 진행 |

실제 테스트에서 사용한 처방은 시연용 이미지다. 후보 선택 검증 후 약 저장은
진행하지 않았으며 환자·보호자의 기존 데모 약과 일정을 보존했다.

자동 테스트는 함량 100/500/1000, mg/mcg, 동등 단위·농도, 복합제 함량,
정제/캡슐·서방/장용, 잘못된 농도 분모, 원문과 자동·AI·캐시 교정의 충돌,
단일 정확 일치와 복수 제조사, 사용자 수정값, 오래된 응답·후보, 화면 너비
360/800, 계정 잠금의 제한된 재시도와 일반 서버 오류를 포함한다.

## 위젯 완료 후 재알림

1. 환자 알림을 10분 뒤로 미룬 뒤 오늘 시간대의 알림 예약을 확인했다.
2. 네트워크 연결을 끈 상태에서 위젯으로 해당 시간대의 복용을 완료했다.
3. 기기에 기록한 완료 상태를 기준으로 오늘 재알림 예약이 제거되는 것을
   Android 예약 목록에서 확인했다. 다음 날과 다른 시간대의 예약은 유지됐다.
4. 오프라인 중 서버는 미완료 상태를 유지했고, 재연결·갱신 후 서버까지 동기화됐다.
   오늘의 취소한 재알림은 다시 만들어지지 않았다.

10분을 실제 대기해 알림이 나타나지 않는지를 관찰한 테스트는 아니며,
Android 예약 상태와 재동기화 결과를 직접 검사했다. 테스트 약과 임시 설정은
정리하고 기존 데모 일정으로 복구했다. 보호자 읽기 전용 위젯과 지난 날짜,
다른 계정·시간대·날짜의 보존은 자동 회귀 테스트로도 확인했다.
