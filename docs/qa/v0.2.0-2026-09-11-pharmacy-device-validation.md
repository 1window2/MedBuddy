## Loading interpretation

One existing-build refresh became inspectably ready within about seven seconds;
one new-build screen entry within about six seconds. These measurements include
ADB inspection overhead, used different operations/times, and do not isolate
GPS, HTTP or native-map initialization. They are not an optimization benchmark.
Code inspection shows location acquisition precedes one backend search, followed
by map initialization. Widget tests verify that opening/closing the list keeps
the map element and does not issue another pharmacy request.

## Limits

This is one-device portrait validation, not exhaustive accessibility/device
coverage or proof of live pharmacy opening status. No external phone call or
navigation journey was tested. Two-device and public-release gates remain open.
