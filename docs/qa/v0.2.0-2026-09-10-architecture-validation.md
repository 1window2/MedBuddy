# v0.2.0 architecture validation — 2026-09-10

## Scope and corrections

Focused review of authentication/authorization, prescription cancellation and
redaction lifecycle, atomic slot completion, caregiver outbox delivery, pharmacy
catalog lookup, and chat deployment boundaries. See
[architecture gates](v0.2.0-architecture-gates.md) for remaining limitations.

- `5a03ec2`: bind notification actions to their original dose date, reject
  mismatches on the server, preserve that date through snooze, and prevent
  cancelled/disposed local OCR operations from starting an upload.
- `2947ab4`: Dart null-aware map syntax required by the configured analyzer.
- `eacd4c8`: document restricted token ACL recovery for the non-root tunnel.
- `20fb2ba`: replace blanket completion Undo with non-mutating schedule review
  in both home and notification entry points; add regression checks.

## Server verification

- Backend deployed with Compose `up -d --build --wait`; no volumes removed.
- Hashes of deployed schedule control, API router and schema match the reviewed
  backend source. Later changes are client/documentation-only.
- Public HTTPS `/health` and `/ready` succeed.
- Unauthenticated `/api/v1/medication/schedule/today` returns 401.
- Preserved catalog rows: drug basics 4,765; approvals 42,987; pill references
  25,381; pharmacies 25,406.
- Found and repaired a real tunnel outage: backend was healthy locally but the
  non-root tunnel could not read the owner-only token file, causing public 530.
  Granted read access only to its container UID via file ACL; group/other access
  remains absent. No token was printed or committed. Recheck after token-file
  replacement or permission changes as described in the deployment guide.
