### Follow-up found: reminder text can include completed doses

The delivered notification still described both dummy medications as due even
though dummy A was already recorded complete. The write action itself preserved
that earlier completion correctly, but the text was based on scheduled names,
not the current incomplete-dose set. `NotificationService._buildReminderBody`
turns that snapshot into wording that says it is time to take those medications.
Before accepting reminder-content UX, either keep the pending-dose text current
through completion changes (including background/concurrent updates), or use
neutral wording that does not imply a previously completed medication should
be taken again. Cover partially and fully completed slots. This is a finding,
not a correction implemented by this physical test pass.

### Reminder-content correction after the physical finding

Commit `a90f146` removes medication-name snapshots and take-now instructions
from both regular and snoozed reminders. Titles identify the schedule; bodies
ask the user to check the schedule and recorded completion status. This stays
accurate even if a slot becomes partially or fully complete after scheduling,
and applies in Korean/English with either notification privacy setting.
Quick actions and their original-dose-date guards are unchanged.

Six Android method-channel regression cases cover stale/empty name snapshots,
both languages/privacy settings, and snooze exact-alarm failure with neutral
inexact fallback and original-date preservation. Flutter analysis and tests
passed in run `34488961103`, including Android release compilation. Backend
run `34488961114` passed: 490 tests passed, 2 skipped,
and the PostgreSQL migration round-trip tests passed (2).

An installed update does not retroactively rewrite stored Android alarm text.
Open the updated app online and complete a successful schedule/reminder refresh
to replace existing alarms. Offline refresh failure deliberately preserves
existing alarms. The new signed build/device check is tracked separately;
the earlier physical pass used the previous APK and is not evidence that the
new text has already appeared on the phone. All remaining gates above remain
open; this is controlled-beta validation, not public-release approval.
