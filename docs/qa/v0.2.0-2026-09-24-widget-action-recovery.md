# 위젯 복용 기록의 저장 중 멈춤 복구

기준: `2bce3e7`, `beta/v0.2.0`.

## 원인과 수정

환자 위젯에서 복용 버튼을 누르면 클릭 요청은 보관됐지만 화면이
`기기에 저장 중`에서 멈췄다. 에뮬레이터의 WorkManager 기록에서
기존 위젯 작업의 실패와, 실행 시도 없이 실패한 후속 작업 8개를 확인했다.

`home_widget` 0.10의 백그라운드 예약은 `APPEND`를 사용하므로 앞선 작업의
실패·취소 상태가 다음 요청에도 전파된다. `DoseWidgetRefreshScheduler`에서
같은 작업 이름과 입력 계약을 유지하면서 `APPEND_OR_REPLACE`로 예약한다.
기존 작업이 정상이면 순서를 유지하고, 이미 실패하거나 취소됐으면 새 요청을 실행한다.
정책의 동작은 [Android 공식 문서](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/manage-work#conflict-resolution-policy)를 따른다.

변경 범위는 Android 위젯의 콜백 실행 예약이다. 기존 Dart 콜백, 암호화된
복약 저장소, 중복 방지 토큰, 서버 전송 절차와 보호자 읽기 전용 권한은 유지한다.
로컬 저장을 위해 네트워크 연결 조건을 추가하지 않으며 실패 복구 시 기록을 삭제하지 않는다.

## 검증

- Android 회귀 테스트 4개 통과: 콜백 입력·오프라인 실행 조건, 실패한 대기열 복구,
  취소된 대기열 복구, 정상 선행 작업과 순서 유지.
- 기존 Flutter 위젯·동기화 테스트 52개 통과.
- 환자·보호자 디버그 앱 빌드와 기존 데이터 유지 설치 확인.
- 환자 홈 위젯에서 앱을 열지 않고 아침 복용 취소 후 재기록 확인.
  저장 완료 후 다음 미복용 일정인 저녁으로 전환됨.
- 데모 서버 연결을 잠시 끊은 상태에서도 로컬 저장 후 버튼 활성화 확인.
  연결 복구와 새로고침 후 전송 대기가 해소되고 서버 저장 완료로 표시됨.
- 시험 후 원래 복용 상태와 서버 연결을 복원함.

실제 기기와 다른 제조사 런처에서의 검증은 별도로 필요하다.
