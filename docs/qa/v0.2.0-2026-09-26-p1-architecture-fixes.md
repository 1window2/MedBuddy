## Chat event-loop isolation

Async chat routes previously called synchronous SQLAlchemy controls directly,
and the WebSocket handshake also performed blocking Firebase verification.
A simulated 200 ms database call delayed an unrelated 10 ms event-loop timer
to 202 ms during the review.

Authorization, message creation/deletion/read marking, dose recording and its
schedule refresh now await the bounded AnyIO worker pool through
`run_in_threadpool`. WebSocket authentication, authorization, link lookup,
commit, rollback and close use the same boundary. The socket's DB session is
closed after its handshake instead of surviving for the entire socket lifetime.

The existing request-scoped REST session remains owned by FastAPI's `get_db`
dependency. Calls using it are sequential, never parallel; request cancellation
must not be implemented by abandoning a still-running worker and closing its
session concurrently. Transaction and authorization policy remain in controls;
socket publication and asynchronous quotas remain in the router. No new
cross-layer dependency or second medication writer was introduced.

Regressions assert worker-thread execution and require an event-loop callback
to run during each simulated synchronous REST operation. Socket cases verify
successful authorization, quota denial and authorization failure, including
cleanup and close-code preservation. This establishes isolation, not a
production throughput or database-timeout guarantee.

## Exact-commit signing gate

`release-android.yml` now has a read-only `verify-ci` prerequisite with no
signing environment. Before the signing job is eligible, it queries the two
named backend/Flutter workflow histories for the exact `GITHUB_SHA` and requires
the latest matching push run/attempt to have completed successfully.

Missing checks, pending reruns, failures, cancellations, PR-only evidence,
malformed responses and API failures do not permit signing. The gate uses the
runner's read-only Actions token and does not print credentials or API exception
contents. If CI is still running, wait and rerun the signed-build workflow.
This does not replace environment approvals, physical acceptance, App Check
configuration or the existing artifact signature checks.
