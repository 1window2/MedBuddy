# Reminder default-time correction

Baseline: `72d6b96`, `beta/v0.2.0`. Addresses the September 22 meeting report
that changing default medication times did not affect newly configured slots.

## Cause and contract

The alarm API synthesized missing slot alarms using product defaults (08:00,
12:00, 18:00, 22:00), overwriting the frontend's patient-specific defaults.
Those synthetic alarms were indistinguishable from saved alarms to the client.

The backend now reads the patient's stored default time for unsaved slots.
Reads remain non-mutating, and disabling an unsaved slot starts from that same
time. Existing saved alarms retain their time and enabled state, including
explicitly disabled alarms. Defaults do not enable notifications automatically.
Alarms are per patient and slot, not per medication: adding a medication to an
already configured slot intentionally retains that slot's saved alarm time.

After a successful server settings save, the frontend reloads alarm display
state when default times changed. This is a read-only refresh; it does not
reschedule native alarms or cancel snoozes. A failed server save retains the
existing pending/local-only settings behavior and does not fetch stale defaults.

The existing Control -> Entity persistence boundary is retained; no schema or
API response change is required. Roll out the backend correction with the app
change; an older backend still returns hard-coded synthetic defaults.

## Validation

- New backend regressions failed against the old implementation, then passed.
- Backend suite: 546 passed, 2 skipped, 21 subtests passed.
- Flutter suite: 939 passed; focused tests also cover failed settings saves.
- Flutter static analysis: no issues.
- Tests cover all four default times, account isolation, read-only lookup,
  changed defaults, and preservation of enabled/disabled custom alarms.

Physical-device verification remains deferred. On designated test records,
verify a fresh slot uses the new default, a customized slot retains its time,
and a pending snooze survives a default-time edit. Caregiver widget refresh,
chat notification routing, and patient/caregiver time-label consistency remain
separate follow-up items; this change does not claim to fix those paths.
