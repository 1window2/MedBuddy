## Implemented next priority

Added a data-preservation rehearsal for the required pharmacy-cache migration
`6d4f8a2c9301`, and added it to the PostgreSQL CI job. It verifies:

- Upgrade from the preceding revision and repeated upgrade are safe.
- The expected expiry index is present.
- Rollback removes only the temporary cache; existing users, links, catalog
  rows, medication schedules, completion records and chat snapshots survive.
- Re-upgrade succeeds after rollback.
- Existing cache rows survive adoption, whether the expiry index exists or
  must be added.
- The preceding revision is rejected by the current revision check.

Tests use temporary SQLite databases and, when explicitly enabled, a unique
PostgreSQL schema inside a transaction that is rolled back. No production
database or real user data is used. No application schema or runtime behavior
is changed; this adds a release regression gate, not a new feature or deployment.
The deployment guide now documents the migration prerequisite and rollback
coordination between backend code and schema.
