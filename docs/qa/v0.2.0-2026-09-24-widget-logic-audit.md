# 환자·보호자 위젯 로직 점검

기준: `b9cff0d`, `beta/v0.2.0`. 이 문서는 해당 커밋 이후의 점검과 수정 결과다.

## 발견한 문제와 수정

로그아웃하거나 다른 계정으로 전환한 뒤 같은 계정으로 다시 로그인하면,
이전 로그인에서 만든 위젯 복용·취소 버튼이 다시 유효해지는 문제를 재현했다.
보호자의 이전 환자 탐색 키와 늦게 도착한 환자 조회 응답에도 같은 문제가 있었다.
새로 추가한 회귀 테스트 중 5개가 수정 전 실패했다.

`DoseOutboxStore.activate`가 활성 계정 변경과 이전 위젯 상태 폐기를 하나의
트랜잭션으로 처리하도록 수정했다. 나가는 계정과 들어오는 계정의 예전 버튼,
환자 탐색 키, 환자 조회 캐시를 폐기하고 조회 버전을 새로 발급한다.
개인별 표시 설정, 본인 일정 캐시, 전송 대기 중인 복약 기록은 유지한다.
같은 계정의 단순 앱 재시작·반복 초기화는 정상 버튼을 무효화하지 않는다.

## 자동 검증 범위

| 구분 | 확인한 내용 |
| --- | --- |
| 환자 기록 | 선택한 시간대의 미복용 약만 기록, 복용 후 다음 일정 표시, 완료된 시간대 취소, 중복 클릭과 오래된 토큰 재사용 거부 |
| 시간대 | 아침·점심·저녁·취침 전, 약이 없는 시간대 생략, 사용자 설정 시각에 따른 다음 일정 순서, 전체 완료·일정 없음 |
| 동기화 | 오프라인 기록과 취소, 프로세스 재시작 후 전송 대기 보존, 순서 유지, 중복 재전송, 서버 거절 상태 |
| 날짜·계정 | 자정 경계, 전날 버튼 거부, 다른 계정 접근 거부, 로그아웃·재로그인 후 이전 버튼 및 환자 탐색 키 거부 |
| 보호자 | 모든 시간대 읽기 전용, 여러 환자, 별칭 변경·재정렬, 연결 해제·재연결, 타 보호자 연동 제외, 늦게 도착한 응답 거부 |
| 표시·개인정보 | 한국어·영어, 약 이름 숨김, 암호화된 저장 상태, Android 위젯 크기·글자 크기 조합 |

네 시간대의 없음·미복용·완료 81가지 조합에 역할 2종, 언어 2종,
이름 숨김 2종을 적용한 **648가지 조합 검사**를 추가했다.
진행률, 시간대 목록, 다음 일정, 복용·취소 권한, 이름 숨김을 함께 검증한다.

- 전체 Flutter 테스트: **987개 통과**. 위의 조합 검사는 테스트 1개 안에서 실행된다.
- 위젯·동기화 집중 테스트: **59개 통과**. 전체 Flutter 결과와 중복 집계하지 않는다.
- Flutter 정적 분석: 문제 없음.
- 서버 `test_dose_sync.py`: **11개 통과**. 실제 데이터가 아닌 격리된 메모리 DB 사용.
- Android 위젯 테스트: **6개 통과**. 작업 실패·취소 후 복구와 정상 순서 유지,
  다양한 크기·글자 크기에서 레이아웃 검증을 포함한다.

## 에뮬레이터 확인

환자·보호자 앱을 각각 수정본으로 갱신했다. 기존 앱 데이터와 배치한 위젯은 유지했다.

1. 환자의 완료된 아침 일정에서 `복용 취소`가 표시되고, 빠른 연속 입력 후에도
   취소 상태가 한 번만 반영되어 진행률이 3/5에서 1/5로 바뀌었다.
2. 데모 서버 연결을 끊고 아침 `복용했어요`를 연속으로 눌렀다.
   진행률은 3/5로 복원되고, 전송 대기는 1건이며 남은 저녁 일정으로 바로 이동했다.
3. 서버 연결 복구 후 앱 열기나 수동 새로고침 없이 `서버 저장 완료`로 바뀌었다.
4. 보호자는 두 환자 사이를 전환할 수 있고, 두 번째 환자의 취침 전 약도 표시됐다.
   복용·취소 버튼 대신 `일정 열기`만 표시됐다.
5. 보호자 새로고침 후 선택한 환자와 취침 전 시간대가 유지됐다.
   `일정 열기`는 선택한 두 번째 환자의 상세 일정으로 이동했다.
6. 보호자 통신 실패 시 환자·시간대·약 정보가 사라지지 않고
   `최근 조회 기준 · 새로고침 필요`로 표시됐다. 복구 후 정상 표시로 돌아왔다.
7. 마지막에 첫 환자로 돌아가 환자와 보호자 양쪽 모두 3/5임을 확인했다.
   시험을 위해 바꾼 복용 상태와 서버 연결을 원래대로 복원했다.

## 검증 한계

계정 전환·자정·연결 해제 등 경계 조건은 격리된 자동 테스트로 확인했다.
데모 계정에서 실제 Firebase 로그인·로그아웃을 반복하거나 기기 날짜를 바꾸지는 않았다.
통신 실패는 데모 서버 연결 차단으로 재현했으며, 비행기 모드·실제 통신망 전환 시험은 아니다.
제조사별 실제 기기, 절전 모드의 장시간 동작, 운영 Firebase·FCM 전달 검증은 별도 확인이 필요하다.
