# 리팩터링 후속 개선 검증

검증일: 2026-10-05. 기준 이력: `58e9761` 이후 DB 연결 반환, 보호자 일정 일괄 조회,
채팅 입력 행 갱신, 병원·약국 마커 부분 갱신 변경.

## 환경

- Flutter 3.41.5, Android Pixel_7 / Pixel_7_Caregiver 에뮬레이터.
- 기존 데모 실행기로 로컬 백엔드와 환자·보호자 앱을 빌드·설치했다. 앱 데이터와 위젯은 유지했다.
- 사용자 마우스를 점유하지 않는 ADB 조작·화면 캡처로 확인했다.
- 실제 건강 추천 요청은 전송할 테스트 약 정보를 먼저 검토하고 사용자 승인을 받은 뒤 실행했다.
- API 키, 로컬 설정·DB, 테스트 캡처는 저장소에 추가하지 않았다.

## 자동 검증

| 구분 | 결과 | 핵심 검증 |
| --- | --- | --- |
| 관련 백엔드 26개 테스트 파일 | 262개 통과, subtest 2개 통과 | 인증·계정 삭제, 건강 추천, 일정·연동·채팅, 카탈로그 및 병원·약국 API |
| 관련 Flutter 6개 테스트 파일 | 103개 통과 | 입력별 목록 재구성 방지, 마커 차이, 보호자 snapshot, 채팅·위치 조회 수명 |
| 수정 Dart 5개 파일 정적 분석 | 문제 없음 | 분석 과정의 중괄호 형식 경고 2곳 정리 |
| UML 원본·이미지 | 로컬 PlantUML 렌더 성공 | 전체 클래스·순서도, 보호자/채팅과 병원/약국 상세도 |
| 기존 주석 보존 | 변경 코드 19개 파일, 기존 주석 누락·변경 0건 | 들여쓰기 제외한 주석 문자열 비교, 새 설명은 한글 |

DB 회귀 테스트는 연결 풀과 worker를 각각 하나로 제한한 상태에서 AI 요청 5개가
대기하더라도 연결을 반환하고 다른 SELECT가 진행되는지 검증한다. AI 대기 중 계정
삭제·삭제 요청·연동 해제·복약 입력 변경·요청 취소도 모의 AI로 재현한다.
계정이 삭제되면 다시 생성하거나 cache를 저장하지 않고, 연동 해제는 403,
계정 삭제는 410, 복약 입력 변경은 409로 거부하는지 확인한다.

보호자 일정은 환자 1·5·20명에서 4회 조회, 401명에서는 6회 조회한다.
기존 단일 환자 응답과 비교해 만료된 약 제외, 과거 형식의 완료 기록,
명시적인 시간대 미완료, 연결되지 않은 환자 제외와 불필요한 상세 필드 제외를 검사했다.

## 관찰 및 한계

- 건강 추천 최초 요청은 일반 오류 화면으로 종료되었다. 같은 테스트 입력의 생성,
  다른 언어의 실제 API 신규 생성, 앱 재시도는 성공했다. 최초 실패의 예외 원인은
  확보하지 못했으므로 외부 API 장애 또는 코드 버그로 단정하지 않는다.
- 병원 정보 일부를 확인하지 못했다는 경고와 진료시간 확인 필요 상태를 관찰했다.
  전체 결과·상세창과 지도는 사용 가능했다. 공공 API 자료의 완전성은 보장하지 않는다.
- 실제 PostgreSQL 서버의 잠금·동시성은 실행하지 못했다. SQLite 연결 풀 실험과
  PostgreSQL 명령·계정 잠금 순서의 mock 계약 검증을 구분한다.
- 계정 삭제·연동 해제 경합은 임시 DB 자동 테스트로 검증했으며 데모 계정을 삭제하지 않았다.
- 프레임 시간이나 실제 단말 배터리 사용량은 측정하지 않았다. 성능 수치는 DB 조회 수와
  widget 재구성·마커 변경 집합 테스트 범위에 한한다.
- 사용자 조작 순서와 화면 구성은 유지되어 사용설명서 PDF/Markdown의 수정은 필요하지 않다.
