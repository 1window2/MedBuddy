# 기능 찾기

## 목적과 화면

홈의 알림 버튼 왼쪽 돋보기에서 기능을 찾는다. 기존 홈 카드와 하단 탐색은
유지한다. 입력 전에는 주요 기능과 전체 기능 목록을 표시하며, 검색 결과에는
기능 이름과 기존 메뉴 위치를 함께 표시한다.

이 문서는 `beta/v0.2.4`의 `77a0f26`까지 통합한 기준과 이후 로컬 구현을
설명한다. 출시·배포 또는 실기기 검증 완료를 뜻하지 않는다.

## 목적지 범위

정적 목록은 27개 목적지다. 같은 화면의 서로 다른 진입 위치도 별도 목적지로
구분하며, 27개의 독립 화면이나 새 기능을 만드는 것은 아니다.

| 영역 | 목적지 | 개수 |
| --- | --- | --- |
| 약 등록·식별 | 직접 등록, 처방전 등록, 알약 사진 식별 | 3 |
| 복약 관리 | 오늘 일정, 필요시 복용, 복약함, 복약 기록, 기록 공유 | 5 |
| 연결·채팅 | 환자·보호자 연결, 연결 환자 일정, 가족 채팅 | 3 |
| 주변·건강·알림함 | 약국, 병원, 건강 관리 추천, 받은 알림 | 4 |
| 설정·안내 | 휴대폰·테스트 알림, 알림 수신, 기본 복약 시간, 잠금 화면 알림 내용, 글자 크기, 언어, 시간 형식, 읽기 속도, 홈 일정, 홈 위젯, 계정, 데이터 이용 안내 | 12 |

입력 전 주요 기능 6개를 먼저 보여주고 나머지를 전체 기능 영역에 표시한다.
위젯 미지원 기기에서는 위젯 목적지를 두 영역과 검색 결과에서 제외한다.

## 검색 기준

- `FeatureSearchEntry`와 `AppFeature`는 허용된 화면 이동 목록이다.
- `FindAppFeature`는 이름, 한국어·영어 동의어, 일상 표현, 의미별 단어 조합을
  평가한다. 공백과 문장부호, 영문 대소문자는 비교할 때 무시한다. 그래서 영어
  단어 조합에는 다른 단어 안에 들어가는 짧은 조각(`not`, `on`처럼
  notification에 포함되는 것)을 쓰지 않는다.
- 정확한 이름·표현을 우선하고, 문장 속 공유 의도나 환자 조회 의도를 구분한다.
  예를 들어 “먹은 약 기록을 가족에게 보내고 싶어”는 기록 공유를, “엄마가 약
  먹었는지 확인”은 연결된 환자의 복약 일정을 우선 표시한다.
- 알려진 표현을 사용하는 로컬 규칙 기반 검색이며, 임의의 질문을 이해하는
  생성형 AI가 아니다. 관계없는 입력은 결과 없음으로 처리한다.
- 검색어는 현재 화면 메모리에만 보관한다. 서버 전송, 분석 로그, 최근 검색어
  저장, 개인 약 이름·채팅 본문 검색은 하지 않는다.
- 입력은 최대 120자다. 검색 결과가 하나여도 자동 이동하지 않으며, 검색 제출은
  키보드만 닫는다. 사용자가 결과를 선택해야 이동한다.

## 이동과 안전 경계

`FeatureSearchUI`는 사용자가 선택한 `AppFeature`만 반환한다. `HomeScreen`이
같은 세션인지 확인하고 기존 화면·Control 진입점으로 이동한다. 새 서버 API나
DB 구조는 추가하지 않는다. 검색 자체는 네트워크 없이 가능하지만 목적 화면의
조회·저장에는 각 기능의 기존 네트워크·권한 규칙을 적용한다.

- 설정은 `UserSettingDestination`으로 기존 분류와 항목 위치를 연다. 설정값은
  자동 변경하지 않으며 기존 저장·미저장 변경 확인을 유지한다.
- 복약 기록은 본인 범위를 사용한다. 환자 조회는 활성 보호자 연동에서 환자를
  확인하고 기존 권한 재검증 경로를 통과한다. 환자가 한 명이면 바로 열고 여러
  명이면 선택창을 연다. 연동이 없거나 조회에 실패하면 연결 관리로 이동한다.
  연동 확인을 기다리는 사이 다른 탭이나 화면으로 옮겼다면 그 위에 열지 않는다.
  가족 채팅도 확인된 활성 연동이 없으면 연결 관리로 안내한다.
- 기록 공유 검색은 최초 조회 성공 후 기존 기간·대상 확인창만 연다. 실제
  다른 앱으로 텍스트 공유 또는 채팅 전송은 사용자의 별도 선택과 기존 검증을 거친다.
- 계정 삭제, 약 삭제, 복용 체크, 알림 켜기 등의 표현도 해당 화면을 찾을 뿐,
  검색이나 결과 선택만으로 데이터 변경·삭제·전송을 실행하지 않는다.
- 플랫폼에서 지원하지 않는 복약 위젯은 결과와 목록에서 제외한다.

## 책임 분리

- Boundary: `FeatureSearchUI`는 입력·표시·선택만 맡고, `HomeScreen`은 중복
  검색창 열림을 막고 같은 ViewModel·계정인지 확인한 뒤 기존 진입점으로 연결한다.
- Control: `FindAppFeature`는 정적 목록의 로컬 매칭과 정렬만 맡는다. 목적 화면의
  조회·권한 검증·저장 책임은 기존 Control에 남는다.
- Entity: `AppFeature`는 허용된 목적지, `FeatureSearchEntry`는 한영 이름·메뉴
  위치·별칭·의도 그룹이다. `UserSettingDestination`은 설정 분류와 스크롤 위치를
  지정하는 화면 인자이며 저장되는 설정값이 아니다.

설정 계정의 welcome 영역 정렬, PRN 최초 로딩 표시, 복용량·위젯·알림 분류의
영어 표시는 함께 반영한 화면 보완이며 검색 매칭이나 서버 데이터 계약을 바꾸지 않는다.
상태 수명은 [프런트엔드 상태 문서](MedBuddy%20-%20Frontend%20Feature%20State.md)를 따른다.
